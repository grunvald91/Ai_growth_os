# React Schedule Redesign — перенос дизайна расписания в SPA

Дата: 2026-06-30

## Контекст
Расписание, которое бот реально открывает (`servgo.ru/schedule?role=owner` → React `/admin/schedule`), отдаётся React-страницей `web/frontend/src/pages/admin/SchedulePage.tsx`. Отдельно есть редизайн в старом aiohttp-стеке (`webapp/templates/schedule.*`), но nginx на бой туда не маршрутизирует. Цель — перенести UX редизайна в React, чтобы он дошёл до пользователей, и двигаться к выводу aiohttp-страниц.

## Цель
Заменить табличный таймлайн (`<table>` + `transform: scale`) на современный календарь-таймлайн с паритетом фич редизайна, в единой дизайн-системе ServGo, со светлой/тёмной темой (Telegram-native).

## Источники данных (без изменений контракта, кроме переноса)
- `GET /api/admin/bookings?business_id&start_date&end_date|date` → `AdminBooking[]`
- `GET /api/admin/businesses/{id}/services|employees`
- `PATCH /api/admin/bookings/{id}/status`
- `POST /api/admin/bookings` (создание)
- **НОВОЕ:** `POST /api/admin/bookings/{id}/reschedule` `{date,time,employee_id?}` (добавлено в `web/api/routes/admin.py`, схема `AdminRescheduleIn`).

## Объём (паритет с патчем)
1. **Тема** — токены в `index.css`: светлая/тёмная, привязка к Telegram `themeParams` через `utils/telegram.ts`; статус-цвета в токены.
2. **Таймлайн на абсолютном позиционировании** — записи позиционируются `top/height` от времени; нет разрывов при скролле.
   - День: колонки по сотрудникам + раскладка пересечений по дорожкам.
   - Неделя: 7 колонок-дней; перегруженный день (3+ одновременно) сворачивается в блок «N записей» → тап открывает день.
3. **Линия «сейчас»**, **легенда статусов** и **сводка** (записи/выручка/загрузка) — сворачиваемые.
4. **Перенос** — кнопка «Перенести» в карточке + drag&drop (день) через новый эндпоинт; оптимистичное обновление с откатом.
5. **Поиск** по клиенту/услуге/телефону + фильтр по мастеру (фильтр уже есть).
6. **Роли** — `role=admin` (день, без создания) vs владелец (всё). Роль берётся из localStorage (`userRole`).
7. Сохранить полезное из текущей версии: автообновление 15с, цветовая карта клиентов, модалки деталей/создания.

## Порядок реализации (пошагово, с typecheck/build после каждого)
1. ✅ Backend `POST /admin/bookings/{id}/reschedule` + схема + `api.adminReschedule()`.
2. Тема и токены в `index.css` (+ применение theme к `<html data-theme>`).
3. Переписать рендер таймлайна (день/неделя) на абсолютное позиционирование + дорожки.
4. Линия «сейчас», легенда, сводка.
5. Перенос (кнопка + drag&drop), поиск, роли.
6. CI: сборка и заливка `web/frontend/dist` в GitHub Actions (сейчас деплоится только `webapp/`).
7. Вывод aiohttp-страницы расписания из эксплуатации (после приёмки).

## Верификация
- `npx tsc -b` и `npm run build` зелёные после каждого шага.
- Локальный `vite preview` + Playwright/скриншоты для визуальной проверки.
- Бэкенд: деплой + `curl` нового эндпоинта (401 без авторизации, успех с правами владельца).

## Риски
- Drag&drop на тач-устройствах — самый хрупкий пункт; при сложностях сначала кнопка «Перенести», DnD — следом.
- Тёмная тема не должна ломать Telegram-WebApp оформление.
- Общий `servgo_auth` — при выводе aiohttp проверить зависимости.
