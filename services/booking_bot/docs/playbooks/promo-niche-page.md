# Playbook: создание промо-страницы для новой ниши

Воспроизводимый процесс для `promo.servgo.ru/<slug>`. Опирается на дизайн-док
`docs/plans/2026-05-31-promo-servgo-niches-design.md` и три эталонные ниши
(`webapp/niches/{beauty,psy,shinomontazh}.yaml`).

## Когда применять

Хочу новую страницу под конкретный сегмент (бани, аренда залов, барбершопы,
репетиторы, автомойки и т.п.). Не для «обобщённой» страницы — её роль уже
закрывает корневой лендинг promo.servgo.ru.

## Workflow

### Фаза 0. Решение и slug

- Slug — kebab-case, только ASCII, lowercase. `get_niche()` отвергает любые
  отклонения (защита от Windows case-insensitive FS).
- Проверить что slug не конфликтует с конкретными маршрутами aiohttp
  (`/login`, `/book`, `/calendar` и т.д.). Catch-all `/{slug}` зарегистрирован
  ПОСЛЕДНИМ, но всё равно лучше не дразнить.

### Фаза 1. Ресерч (делегировать document-specialist)

Параллельный агент собирает дозье в `docs/niches/<slug>-research.md`:

- **10 болей с источниками** — статьи, форумы, отзывы. Цифры и цитаты.
- **5 конкурентов** + их слабые места (но на страницу по имени НЕ выносим, см. правила).
- **Топ-10 услуг** для `stage_services` и `hero.slots`.
- **Топ-объекции владельцев** — для FAQ.
- **Каналы дистрибуции** — где живёт ЦА (Instagram Bio, Telegram-каналы, локальные паблики, профильные форумы).

### Фаза 2. Топ-5 болей

Дистиллируем 10 болей в 5, дописываем в `docs/niches/_top-pains.md`:

- Конкретика, цифры, локальный сленг.
- Каждая боль явно или неявно намекает на решение ServGo.
- НИ ОДНОЙ английской кальки (no-show → пропуск, walk-in → клиент с улицы).

### Фаза 3. Заполнение YAML

Структуру брать из `webapp/niches/beauty.yaml` или `shinomontazh.yaml` —
там полный набор полей. Полный шаблон в конце документа.

**Ключи-ловушки** (НЕ менять, не путать):

- `pains.entries:` и `faq.entries:` — НЕ `items:`. Слово `items` резолвится в
  `dict.items` метод и роняет шаблон с `TypeError: 'builtin_function_or_method'
  object is not iterable`.
- В YAML ключ `copy:` — норм. Но в `niche.html` он читается как `niche.X['copy']`,
  потому что `niche.X.copy` уходит в `dict.copy` метод и в HTML вылезает
  `<built-in method copy of dict object at 0x...>`. Изменения шаблона уже сделаны
  — не откатываем.
- В `signal_strip`, `owners.cards`, `compare.rows` цвета: `mint`, `peach`, `sky`,
  `lemon`, `coral`, `violet`. Других в landing.css нет.

### Фаза 4. Редакционные правила (выстрадано)

**Запрещённые слова и почему:**

| Слово / приём | Замена | Почему |
|---|---|---|
| `no-show` / `ноу-шоу` | `пропуски`, `сорвавшиеся записи`, `клиент не пришёл` | Английская калька, режет глаз русскому владельцу |
| `b17` / `b17.ru` | — (просто убрать упоминание) | Сами «зануды грешные, докопаются» (©Артур). Никогда не упоминаем |
| `YCLIENTS`, `DIKIDI` | `крупные платформы`, `тяжёлые CRM` | Тот же принцип — крупный SaaS, не дразним юристов |
| `RemOnline` | `зарубежные CRM` | + плавающий курс — это конкретная боль |
| `30% маркетплейсу` (в H1) | `комиссия сторонним сайтам` | «Маркетплейс» в H1 не считывается. В compare-секции можно — там контекст |
| Любая прямая цитата конкурента | пересказ своими словами | Защита от претензий |

**Тон Hero copy** (то, что Артур называет «продающий, а не пустой»):

1. **Денежный крюк** — что владелец теряет каждый день/месяц.
   Пример: «каждый дозвон — деньги, каждый пропущенный — клиент у соседей».
2. **Конкретное облегчение** через ServGo — без фич-листа, через результат.
   Пример: «общее расписание, без блокнотов и переписок до полуночи».
3. **Баланс/свобода** — больше времени на себя, семью, спорт, прогулки.
   Пример: «меньше нервов в директе — больше живых записей и времени на свою жизнь».

«Пустой» текст: фичи без цены, общие фразы вроде «удобно и просто», «современно».
Если убираешь фразу и смысл не теряется — фраза пустая.

**Pains — пара пайн + намёк на решение.**

❌ `Клиент не пришёл — час потерян, денег нет. (b17.ru)`
✅ `Клиент не пришёл — час потерян, денег нет. С предоплатой через ServGo час
   оплачен заранее: даже если клиент сорвался, деньги уже у вас.`

### Фаза 5. Деплой

Порядок строго: pull-from-prod → diff → правки → validate → upload → restart →
curl-проверка → commit.

- **pull-from-prod ОБЯЗАТЕЛЕН** — на проде регулярно живут правки, которых нет в git.
  Если перезаписать слепо — потеряешь чужие изменения. Если diff показывает
  расхождение → закоммитить пуленную версию ПЕРВЫМ отдельным коммитом
  («fix(booking_bot/niche): sync <slug>.yaml from prod»), потом править.
- **Jinja2 кэширует шаблоны** — без `systemctl restart booking-bot.service` правки
  YAML НЕ применятся (точнее применятся только если в `__init__.py` стоит
  `NICHES_RELOAD=1`, но в проде это не стоит).
- **curl-проверка** — два запроса:
  1. На наличие новых ключевых фраз (`grep -oE`).
  2. На отсутствие запрещённых слов (`grep -Ei "no-show|b17|YCLIENTS|..."`).
- **Commit** — Conventional Commits на английском с trailer
  `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>`.
  Атомарно: одна правка = один коммит. Не сваливать «синк с проды» в один
  коммит с новыми правками.

### Фаза 6. Визуальная проверка

Открыть в браузере с Ctrl+F5 (Jinja может закэшировать, но и Chrome тоже).
Что смотреть:

- Hero не съезжает на мобильном, кнопки центрированы.
- `signal_strip` — четыре карточки в ряд на десктопе, по одной на мобильном.
- `client-steps` — подписи `<small>` идут нормальной строкой, а не вертикальной
  «лесенкой» (фикс жил в `webapp/static/css/niche.css` — `.step-text { min-width: 0 }`).
- `band-final` — H2 и кнопки по центру.
- FAQ — `<details>` открываются, первый по умолчанию открыт.

## YAML-шаблон (скелет)

```yaml

  description: "<150–160 символов с ключевыми фразами для SEO>"
  og_image: "/static/niche/<slug>/og.png"

  eyebrow: "Онлайн-запись для <ниши>"
  h1: "<селлинг H1 с пользой, не общими словами>"
  copy: >
    <денежный крюк>. ServGo принимает запись 24/7 в Telegram-боте и на сайте
```

`final` подтягиваются из `_shared.yaml` через deep-merge — переопределять не надо,
если хочется кастом, кладём поверх в `<slug>.yaml`.

## Известные баги и фиксы (не повторять)

- **`<built-in method copy of dict object at 0x...>`** в финальном блоке →
  в шаблоне используется `niche.X['copy']`, не `niche.X.copy`. В YAML ключ
  пишем как `copy:` — это нормально.
- **`TypeError: 'builtin_function_or_method' object is not iterable`** →
  использовали `items:` как ключ. Только `entries:`.
- **Вертикальная «лесенка» в client-steps на мобильном** → CSS Grid
  auto-placement кидал `<small>` в узкую 54px колонку. Фикс: `.step-text` wrapper +
  `min-width: 0; overflow-wrap: anywhere` в `webapp/static/css/niche.css`. Не убирать.
- **`/Beauty` грузит `beauty.yaml`** на Windows (case-insensitive FS) →
  `get_niche()` отвергает не-lowercase slug. Не ослаблять.
- **Шаблон не обновился после правки YAML** → нужен `systemctl restart
  booking-bot.service`. Jinja2 кэширует.
- **Конфликт с конкретными маршрутами** (`/login`, `/book`) → `/{slug}` зарегистрирован
  ПОСЛЕДНИМ в `webapp/server.py`. Не двигать порядок регистрации.
