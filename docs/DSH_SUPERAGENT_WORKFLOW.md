# Как владелец запускает задачу агенту (Superagent)

Короткая памятка: как поставить задачу агенту DSH Superagent и что происходит
дальше. Первая версия принимает задачи **только для репозитория
`grunvald91/Ai_growth_os`**; вход через Telegram пока не подключён.

## Шаг 1. Открыть workflow

1. Перейти в репозиторий [`grunvald91/My_ai_assistent`](https://github.com/grunvald91/My_ai_assistent).
2. Открыть вкладку **Actions**.
3. Слева выбрать **`Superagent - submit task`**.
4. Нажать **Run workflow** и убедиться, что выбрана ветка **`main`**.

## Шаг 2. Заполнить поля

| Поле | Что указать |
| --- | --- |
| `title` | Короткое название задания, до 180 символов, без секретов и личных данных |
| `instructions` | Что проверить или исправить, своими словами; до 6000 символов. Результат появится в GitHub Issue |
| `task_type` | `report-only` — только анализ и отчёт, без изменений файлов и PR. `code-change` — разрешены исправления кода и PR |

Нажать **Run workflow**.

## Шаг 3. Что создаёт workflow

Workflow открывает GitHub Issue в репозитории `grunvald91/Ai_growth_os` с
упоминанием `@Grunvald1991`. В теле Issue — инструкция из поля `instructions`
и режим работы (`report-only` или `code-change`). Ссылку на созданный Issue
workflow также показывает в сводке запуска (Summary).

В режиме `code-change` в Issue дополнительно записано, что запрещены merge,
deploy, изменение production, секретов и данных.

Если запуск завершился ошибкой, сообщение подскажет причину: не задан секрет
`GH_PAT`, слишком длинное название или инструкция, или токен не принадлежит
владельцу `grunvald91`.

## Шаг 4. Проверить ответ агента и Pull Request

1. Открыть созданный Issue в `grunvald91/Ai_growth_os` и прочитать ответ агента.
2. В режиме `code-change` агент может открыть Pull Request — в нём видно, какие
   файлы изменены, и почему.
3. **Не сливать в `main` автоматически.** Владелец сам проверяет Pull Request и
   решает, принимать ли изменения.
4. Место, где ведётся обсуждение и в каком состоянии задача, — исходный Issue.

## Главное

- Задачи принимаются для одного репозитория — `grunvald91/Ai_growth_os`.
- Вход через Telegram пока не подключён: единственный способ поставить задачу —
  этот workflow.
- В полях задания не должно быть секретов, токенов и персональных данных:
  Issue, логи и Pull Request видны всем, репозиторий публичный.
- Режим `report-only` ничего не меняет в коде; изменения возможны только в
  режиме `code-change`, и только после проверки владельцем.
