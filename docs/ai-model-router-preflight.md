# Model Router: предпусковая проверка без API-запросов

Цель: проверить панель управления командой до первого включения на сервере. Проверки не обращаются к ClaudeHub и не требуют дополнительных поисковых сервисов.

## Проверки локально или в Codespaces

1. Установить зависимости проекта обычным способом, без GitHub Actions.
2. Выполнить:

```bash
python -m compileall -q app tests
python -m pytest -q tests/test_team_dashboard.py tests/test_router_preflight.py tests/test_model_router.py tests/test_model_router_composition.py tests/test_model_router_costing.py tests/test_model_catalog.py
python -m app.llm.router_preflight
```

Отдельный модуль `router_preflight` проверяет 27 должностей и 4 контент-этапа, основную модель и модель критика, настройки каталога, сохранённую конфигурацию. Он возвращает JSON; никаких токенов владельца, данных клиентов или ключей API в отчёт не выводит.

Если роутер выключен, отсутствие премиальной модели не блокирует существующих агентов: в отчёте будут предупреждения, exit code 0. Если роутер включён, а обязательные маршруты отсутствуют, команда завершится с exit code 1.

## Перед развёртыванием

- Подтвердить фактические ID моделей у ClaudeHub. `GET /models` — только наличие в каталоге; поддержка веб-поиска не подтверждается.
- На API-контейнере задать отдельный случайный секрет длиной не менее 32 символов. Создать его можно локально: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Никогда не записывать значение в GitHub или чат.
- Проверить что `PRODUCTS_ROOT` общий для API и worker и записывается без ошибки; существующее хранилище `company_products` уже монтируется в эти контейнеры.
- При необходимости зафиксировать реальные тарифы для каждой модели, иначе стоимость останется неизвестной. Бюджетный потолок оценивает **один вызов**, не заменяет провайдерские лимиты.
- В браузере открыть `/studio/team` через HTTPS; проверить вход, редактор ролей, кнопку проверки, сохранение, защиту 401 для запросов без токена, отчёт по одному проекту.
- Включать роутер только после проверки основного и резервного маршрутов; не включать его одновременно с неподтверждёнными шлюзовыми идентификаторами.
- Проверить 1 тестовое задание и факт `AgentRun.model` / `CostRecord`; не запускать массовую генерацию.
- Убедиться, что после сохранения изменённой модели следующий worker-вызов использует новую конфигурацию. Старые активные запросы могут завершиться со старой.

## Ограничения нынешнего этапа

Панель и маршрутизатор **не реализуют** реальные поисковые инструменты, оценку доступности сайтов из России, автоматический запуск критиков, сквозную авторизацию клиентов или жёсткое ограничение месячных расходов. Кнопка «Проверить настройки» — структурная проверка, не гарантирует успешную платную генерацию и не подтверждает региональную доступность.

Само сохранение изменений в GitHub **не развёртывает** их на сервере. Для первого запуска потребуется отдельная контролируемая публикация с резервной копией конфигурации и возможностью быстро вернуть `MODEL_ROUTER_ENABLED=false`.
