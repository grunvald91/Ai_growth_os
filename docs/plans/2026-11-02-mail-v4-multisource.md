# ServGo Mail V4 — массовый поиск и безопасная отправка

## Что изменено
- Вкладки снизу остаются Поиск / Рассылки / Письма. Контакты не выделены в четвёртую вкладку.
- По умолчанию поиск через 2ГИС (как раньше). Внешний Exa включается вручную, только при наличии `EXA_API_KEY` **на сервере BookingBot**, не в браузере и не в GitHub Actions.
- В My_ai_assistent есть пример интеграции: `tgcloud/lib/exa.js` и секрет `EXA_API_KEY`. GitHub Secrets не позволяет прочитать значение существующего секрета из другого репозитория. Перенос ключа требует отдельной безопасной настройки среды; ключ не копируется в git.
- Exa: `POST https://api.exa.ai/search`, type auto, по умолчанию до 20 результатов на одно задание (настраивается `SERVGO_EXA_MAX_RESULTS`, максимум 50); проверка сайтов пакетами по три. Поиск не гарантирует, что все сайты содержат email или что все компании соответствуют нише. Может вернуть меньше заданного лимита.
- 2ГИС: не более одного запроса одновременно с паузой `SERVGO_SEARCH_PAUSE_SECONDS` (по умолчанию 5 секунд **перед каждой карточкой**). Это преднамеренный лимит ради корректного поведения при отказе источника.
- Целевое количество означает **подходящие компании с email**, а не просто все адреса; при отсутствии достаточного числа выводится честный итог.
- Оценка по умолчанию: только `hub()` (ClaudeHub), независимо от наличия `OPENROUTER_API_KEY`; Jev отключён. Чтобы включить Jev 1.14 через `/api/alpha/decisions`, нужны `OPENROUTER_API_KEY` и явное `SERVGO_MAIL_USE_JEV=true`. Уверенная рекомендация при вероятности >= 0.85, отрицательная <= 0.20, середина «проверить вручную». Если Jev включён, но ошибся, результат остаётся непроверенным, если специально не выставлен `SERVGO_MAIL_JEV_FALLBACK_TO_HUB=true`. Организации без email сохраняются, но не отправляются на ИИ-оценку. Это не доказательство пригодности компаний.
- UI показывает количество проверенных и прошедшее время, историю 30 последних поисковых заданий, ручной выбор, отметку «подходит/не подходит», переход к новой кампании без потери результатов, возможность продолжить `interrupted/error`.
- Импорт принимает конкретные `firm_ids`; результат помечается импортированным только если фактически присутствует email в целевой кампании. Исторические результаты не требуют готовой кампании.
- При перезапуске сервера задание может получить `interrupted`, затем владелец возобновляет его. Уже изученные сайты/карточки пропускаются. Автоматическое восстановление ещё не включено; повторный запрос к Exa при возобновлении расходует квоту.
- Стадии «подготовить → согласовать → запустить» сохранены, как и глобальный выключатель автоматической рассылки.

## Условия безопасности перед отправкой
- Для чужой организации используется её подтверждённый серверный отправитель. При отсутствии настройки запуск запрещён (не подменяем имя отправителя именем ServGo).
- Параметр `SERVGO_MAIL_COMPANY_SENDERS` задаётся **только в защищённом окружении** в виде JSON:
  `{"company-uuid":{"email":"owner@verified-domain.example","name":"Имя компании","verified":true}}`
  Флаг `verified` должен выставляться оператором только после проверки владения ящиком и авторизации SMTP/SPF/DKIM/DMARC. Одна конфигурация не доказывает фактическую доставляемость; нужен отдельный тест SMTP на контролируемый адрес.
- Endpoint запуска теперь требует `legal_basis_confirmed=true`; UI явно спрашивает владельца. Это **только фиксация заявления владельца**. Проверка каждого основания для рекламной отправки, хранения доказательств согласия и применимого законодательства остаётся обязательной организационной задачей; публичный адрес из поиска сам по себе не равен согласию.
- Отписки/исключения, утверждение каждого письма, остановка отправки и дневные ограничения сохранены.

## Ограничения и оценка времени
- 2ГИС: нижняя граница чистых пауз для N просмотренных карточек = N * 5 сек по умолчанию, сверх этого добавляются запросы к 2ГИС, сайтам и ИИ. Например, 100 карточек только по паузам = 500 сек (8 мин 20 сек); фактическое время больше.
- Exa: один запрос за заданием и до 50 сайтов, обрабатываемых группами до трёх. Время зависит от размера выдачи, соединения, сайта, доступности Exa/Jev и fallback. Нельзя обещать конкретный ETA без измерений на сервере.
- Реальная стоимость Exa зависит от типа запроса и количества результатов, и списывается с отдельного аккаунта Exa. Проверять остаток в его кабинете; никакие фиксированные «бесплатные месячные запросы» в коде не подразумеваются.

## Что проверить перед выпуском
1. Изолированные Python-тесты `pytest -q tests/test_mail_company_search.py tests/test_mail_campaign_safety_v4.py tests/test_mail_air_v2.py tests/test_mail_same_origin.py` (локально; GitHub Actions не тратить до итогового контрольного прогона).
2. На узком viewport: Поиск → выбрать источник → начать → открыть историю → отметить карточки → создать новую рассылку → перенести выбранное → открыть кампанию.
3. На тестовой Exa-квоте: одно задание <= 10 результатов; проверить фактическую структуру API, расхождения классификации и скорость. Никакие реальные письма не отправлять.
4. Проверить 2ГИС отказ/429, сохранение частичных результатов и работу кнопки возобновления только на безопасных статусах.
5. Проверить, что при отсутствии `SERVGO_MAIL_COMPANY_SENDERS` чужая компания получает понятную ошибку и письмо не уходит.
6. Проверить отправку на собственный тестовый ящик после настройки подтверждённого адреса; SPF/DKIM/DMARC и отписка.

Состояние: рабочая ветка, не production. Потребуются доступ к среде BookingBot и отдельная проверка браузера/pytest перед PR и слиянием.
