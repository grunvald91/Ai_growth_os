# ServGo Mail Air V2 — редизайн почтового кабинета (ветка разработки)

Дата: 01.11.2026. База ветки: BookingBot `main` на момент создания.
Предыдущая тема ServGo Air уже была в `main` через BookingBot PR #109.
**Статус этого документа: код новой оболочки в feature-ветке; merge и
production-деплой не выполнены.**

## Цель и границы

Привести оба существующих защищённых кабинета `mail.servgo.ru`
(«Почта и ответы», «Почтовые кампании») к визуальному языку пользовательского
пути ServGo Air на телефоне и десктопе. Реализовать без нового backend,
переименования API/JS идентификаторов, новых SMTP/IMAP запросов и новых прав.

Не заменять почтовый сервис демонстрацией. Фактические контакты, входящие,
исходящие, ИИ-черновики, поиск компаний, очередь, проверка материалов и
автоматическая рассылка продолжают использовать прежние endpoint и подтверждения.

## Уже выполнено в этой ветке — фаза Mail UI 1

- Обе страницы получили общую оболочку ServGo Air V2 через имеющиеся
  `servgo-air-tokens.css` и `servgo-mail-air.css`; темы Light / Dark / System.
- Один стиль навигации, заголовков, карточек, модальных окон, полей и состояний.
- На телефоне обе страницы имеют нижнюю навигацию, вынесенное действие написания
  письма, safe-area inset и более предсказуемые прокрутки списков и действий.
- Сохранены все исходные endpoint, роли, `id`/JS-события и защита отправки;
  изменены только разметка/стили, не программные действия.
- Статические регрессионные тесты проверяют сохранение рабочих контролов,
  наличие общего CSS и границы адаптива.

## Что осталось по этому модулю

1. Проверить в реальном браузере светлую/тёмную темы и ширины 320/375/768/
   1280 px; клавиатуру, dialog, списки писем и таблицы кампаний.
2. Проверить авторизованные сценарии на staging: открыть письмо, ответить,
   написать черновик, найти адресатов, создать кампанию, вернуться назад.
   Использовать fake/mock SMTP — **никаких массовых реальных отправок**.
3. Подготовить сквозной маршрут установленного единого PWA до Mail и обратно,
   учитывая `SERVGO_MAIL_GATEWAY_ENABLED` и сохранение старого
   `https://mail.servgo.ru`. Новая тема сама по себе этого не делает.
4. Проверить физический Android, iOS Safari и десктоп; доступ `mail_owner`,
   401/403, Origin/CSRF, logout/no-store. Mail/Growth офлайн-данные не включать
   без отдельного решения.
5. Проводить review и CI в отдельном draft PR. Объединять его в main
   только после функциональной и визуальной приёмки; staged release отдельно.
   **Не объединять в main и не развёртывать только ради визуальной проверки исходников.**
