# SEO-завод: планирование для каждой подключённой компании

## Реализованный безопасный режим

- `SEO_AUTORUN_ENABLED=false` — глобальный выключатель по умолчанию. До завершения контрольного испытания #241 его не включать: реальные вызовы моделей платные.
- `SEO_AUTORUN_INTERVAL_DAYS=7` — интервал между запусками плана **по каждой компании** (общая настройка оператора, не индивидуальная настройка владельца).
- Владелец должен отдельно включить SEO-завод в своей компании (`seo_factory_activations.enabled=true`). Для демо-компаний и отсутствующих записей включение по умолчанию запрещено.
- При включённом глобальном флаге один тик worker ставит **не более одного** недельного SEO-плана для одной подходящей компании. За разные тик-и обслуживаются разные организации, без перекрёстных бизнес-данных.
- Поиск сроков, проверка текущих задач, отмена по opt-out и создание новых проходят с блокировкой строки `Product`. Ручной/месячный запуск сбрасывает недельный отсчёт. Существующие статьи и задачи другой компании не влияют на расписание.
- Старый пилот `SEO_SERVGO_AUTORUN_ENABLED` сохранён; при выключенном глобальном режиме он работает только для ServGo и не подключает другие организации.

## Оставшиеся ограничения

- По умолчанию глобальный autorun **не работает на продакшене**: включение планируется только после проверки трёх коммерческих статей, маршрутов CTA, критика и отказных сценариев (#241).
- Интервалы, количество публикаций в сутки, время/часовой пояс пока задаются глобально, а не индивидуально для каждого владельца. Настройка через Studio ещё должна быть реализована (#238 / #242).
- Недельный план не означает ежедневную гарантированную публикацию: ошибки модели и критика продолжают блокировать небезопасный материал.

## Критерии для следующего выпуска

1. Две тестовые компании с разными профилями включены отдельно, третья не включена; только первые две получают разные задачи/контент.
2. Повторный тик не создаёт дубли.
3. Отключение SEO у одной компании отменяет её новые запуски без влияния на другую.
4. Ручной/месячный запуск учитывается и не вызывает немедленного недельного дубля.
5. CI, защищённый деплой и реальный контролируемый test run перед включением глобального флага.

См. [задача #238](https://github.com/grunvald91/Ai_growth_os/issues/238) и [сквозная приёмка #241](https://github.com/grunvald91/Ai_growth_os/issues/241).
