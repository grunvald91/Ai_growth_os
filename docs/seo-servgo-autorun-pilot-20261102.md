# ServGo: SEO-завод для органического привлечения покупателей (2 ноября 2026)

Статус: **только кандидат к выпуску**. Ни один флаг production, платный LLM-запрос, публикация или деплой не меняются этим PR. Автоматический цикл не должен быть включён до проверки публичного сайта и редакционной цепочки.

## Задача

Публиковать проверенные, полезные статьи для предпринимателей, которые выбирают систему онлайн-записи, управление расписанием, CRM, напоминания, предоплату или AI-маркетинг; подводить их к реальной демонстрации возможностей ServGo, без придуманных функций/тарифов или обещаний результата.

Профиль Growth с `products.slug=servgo` — единственный разрешённый для этого пилотного автопланировщика. Компании-клиенты не затрагиваются: для них остаётся отдельный явный opt-in и запуск владельцем.

## Как работает кандидат

- Раннее отключение: `SEO_SERVGO_AUTORUN_ENABLED=false` (значение по умолчанию).
- Условие запуска: профиль ServGo существует и его `seo_factory_activations.enabled=true`; остальные компании и demo не запускаются.
- Периодичность: `SEO_SERVGO_AUTORUN_INTERVAL_DAYS=7`, не более `SEO_SERVGO_AUTORUN_MAX_RUNS_28D=4` запусков за скользящие 28 дней.
- Каждый запуск остаётся обычным `seo_factory` и ставит не более трёх статей в очередь, по существующей `MAX_ARTICLES_PER_RUN=3`. Дневная квота генераций отдельно ограничена `SEO_ARTICLES_PER_DAY=3`.
- При наличии выполняемого/ожидающего SEO-задания, незаконченной статьи либо статьи, отложенной критиком на просмотр, **новый запуск не назначается**.
- Автоматическая публикация только после успешного вердикта критика **для точной версии финального текста** и существующих статических/дубликатных проверок; при сбое статья остаётся на согласовании. Флаг не обходит редакционную систему.
- Это лимит заданий, **не** гарантия количества созданных/опубликованных URL, частоты реальной индексации или заявок.

## Обязательные условия перед включением

1. Свести интеграцию Growth с основным кодом без потери текущих изменений студии; применить миграцию `alembic/versions/0011_seo_factory_opt_in.py` согласованно, с резервной копией. Ничего из этого PR не деплоит самостоятельно.
2. Проверить, что `https://servgo.ru/blog`, несколько существующих статей, `/robots.txt`, `/sitemap.xml` и при необходимости `/business-blog-sitemap.xml` публично доступны: HTTP 200/404 согласно смыслу, правильные canonical, `index,follow`, валидная разметка. Прогонять `booking_bot/scripts/seo_public_release_smoke.py` с публичного выхода, затем вручную открыть реальную статью в телефоне.
3. Проверить, что публикация профиля `servgo` физически появляется на **servgo.ru**, со всеми разделами, фактами, датами, CTA и ссылками на конкретное предложение платформы. Отличать внутреннюю запись `Publication` от публичного HTTP 200.
4. Проверить профиль ServGo: функции/цены и CTA должны соответствовать реально работающим возможностям. Для основных тем из поисковых подсказок оценить пользовательскую задачу; не выпускать типовые перестановки ключей.
5. Провести **один** ограниченный реальный прогон генерации с оплатой запросов, посмотреть фактические статьи и отказы критика, ошибки/повторы. Снять фактический расход, не выводить из числа вызовов стоимость на глаз.
6. Подключить подтверждённый `servgo.ru` к Google Search Console и/или Яндекс Вебмастеру, проверить реальные ответы существующих read-only адаптеров, отправить sitemap через официальный кабинет (а не выдавать HTML-тест за индексацию). Вести метрики по опубликованным URL: показы, клики, переходы к демонстрации, обращения и оплаченные подключения — когда они доступны.
7. Только после прохождения этих gates выставить переменную окружения **на Growth worker**, `SEO_SERVGO_AUTORUN_ENABLED=true`, при сохранённом ограничении по компании и частоте. Наблюдать хотя бы первую автоматически сформированную партию и не повышать лимиты до данных о качестве.

## Откат

`SEO_SERVGO_AUTORUN_ENABLED=false` выключает **новое** автоматическое планирование. Для остановки ещё не начавшихся SEO-задач отключить `seo_factory_activations` профиля ServGo штатным контролем компании: он отменяет ожидающие задачи, но не прерывает активные вызовы. Уже опубликованные статьи не исчезают сами; их видимость регулируется отдельно, с сохранением URL.

Сами правила трафика: [Google people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content), [Google spam policies](https://developers.google.com/search/docs/essentials/spam-policies), [Google AI features](https://developers.google.com/search/docs/appearance/ai-features). Система не гарантирует индексацию и цитирования AI-системами.
