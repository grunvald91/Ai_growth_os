# ServGo SEO: еженедельная автоматика и план на 30 дней

Статус: изменения подготовлены в draft PR. Production, секреты, база и реальные LLM-вызовы этим PR не затронуты.

## Запуски

- `SEO_SERVGO_AUTORUN_ENABLED=false` по умолчанию. При включении и подтверждённом owner opt-in для профиля `slug=servgo` новый SEO-план автоматически создаётся раз в 7 дней.
- В интерфейсе `/studio/products/{id}/seo/queue` есть ручной выбор периода: 7 или 30 дней. Месячный запуск создаёт план на месяц и помещает все подтверждённые планом темы в очередь, без отсечения первых трёх статей.
- `SEO_ARTICLES_PER_DAY=0`: снят прежний дневной лимит. Владелец может настроить положительное значение, если понадобится. Нет отдельного ограничения «четыре запуска за 28 дней».
- Публикация остаётся асинхронной и не гарантирует определённого числа статей: поисковые подсказки и качество тем могут дать разное количество.

## Один цикл критики для SEO-статьи

1. Промежуточные этапы статьи создают материал по своему контракту. Критик вызывается один раз для финальной редакции, а не заново для каждого из шести промежуточных этапов.
2. Критик возвращает привязанные к тексту замечания, важность и предложенное исправление. Автор отдельно принимает или отклоняет каждое замечание с мотивировкой.
3. При согласии с замечаниями выполняется одна доработка автором. Повторная оценка критиком запрещена: результат проходит проверку схемы, фактов, дубликатов и совпадения хеша итоговой версии с сохранённым решением.
4. Если автор аргументированно отверг все замечания, публикация разрешена лишь при наличии полного журнала решений, хеша финального текста и остальных технических проверок.
5. Если критик недоступен или исправленный текст не соответствует схеме, автоматической публикации нет, статья остаётся на согласование.

Только после этого включать недельную автоматику на Growth worker. Код не доказывает, что страницы уже индексируются.

Откат: `SEO_SERVGO_AUTORUN_ENABLED=false` останавливает новые автоматические задания. Выключение SEO у компании отменяет задачи в очереди, но не прерывает уже начатые вызовы. Уже опубликованные страницы остаются доступными до отдельного изменения видимости.

Источник требований к контенту: https://developers.google.com/search/docs/fundamentals/creating-helpful-content, https://developers.google.com/search/docs/essentials/spam-policies.
