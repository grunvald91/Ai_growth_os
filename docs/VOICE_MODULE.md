# Голосовой модуль: диктовка с правкой по смыслу

Один общий сервис внутри AI Growth OS: принимает запись, возвращает чистый текст («вин» → VIN). Все продукты подключают его
одинаково. План и решения владельца: документ «Голосовой модуль AI Growth OS: план и архитектура». Здесь — как это
устроено в коде (этап 1 «Каркас»).

## Конвейер (`app/voice/service.py`)

1. **Отсев тишины до распознавания** (`silence.py`): запись короче 0,3 с, меньше ~1,2 КБ или тихий WAV — сразу пустой
   результат, ни распознавания, ни модели. Остальные форматы (webm, ogg) тишину по звуку не проверяются: их ловит шаг 3.
2. **Распознавание** (`stt.py`): OpenRouter, эндпоинт `/audio/transcriptions`, модель по умолчанию `openai/whisper-large-v3`
   (`VOICE_STT_MODEL`), язык ru. Подсказка со словарём собирается, но OpenRouter в multipart её игнорирует, поэтому по
   умолчанию не отправляется (словарь работает на шаге 5). Если модель не умеет подробный ответ, запрос повторяется в
   простом формате. Цена звонка берётся из ответа OpenRouter.
3. **Фильтр выдумок на тишине** (`silence.py`): сегменты с высокой вероятностью «не речь» и типичные фразы
   («Продолжение следует», «Субтитры сделал…») отбрасываются, остаётся пустой результат.
4. **Слова по звучанию** (`dictionary.py`): из словаря берутся только слова, похожие на слова готовой расшифровки
   (до 10), а не весь словарь.
5. **Правка** (`cleanup.py`): быстрая модель Claude через ClaudeHub, температура 0, текст диктовки обёрнут в теги как
   данные. Модель только правит, не отвечает.
6. **Проверка кодом**: нет тегов, пусто, ответ начинается как ответ («Конечно», «Вот»…), длина изменилась слишком
   сильно, ответ оборван — отдаётся сырой текст. Сбой или тайм-аут модели тоже возвращают сырой текст: диктовка не теряется.

Не сделано в этом этапе (следующие по плану): критик «правка или ответ», проверка форматов VIN и госномера, личные
профили и словари проектов в базе, обучение на ручных правках, слои свежести, фоновый агент.

## Точки входа (`app/api/voice.py`)

Оба принимают `multipart/form-data`: `audio` (файл), `project` (необязательно, имя проекта для словаря), `context`
(JSON-список последних 1–3 реплик диалога), `duration_ms` (необязательно), `language` (по умолчанию `ru`).

- `POST /studio/voice/dictate` — для страниц Студии (вход и проверка источника Студии).
- `POST /studio/voice/service/dictate` — для ботов и других страниц, заголовок `X-Voice-Key`, поле `user` обязательно
  (идентификатор человека для личного словаря). Без `VOICE_API_KEY` на сервере или с неверным ключом — 401.

Ответ: `text` (исправленный), `raw_text` (как распознано), `empty` и `empty_reason` (`too_short`, `silence`,
`too_long`), `cleaned`, `fallback_reason`, `replacements` (список замен для подсветки), `event_id` (для будущей ручной
правки), `duration_seconds`. Ошибка распознавания — 502, нет ключа распознавания на сервере — 503.

## Что хранится

Таблица `voice_usage`: кто, проект, исход, длительность, модели, токены, задержки и оценка расхода. **Ни аудио, ни текста
диктовки.** Таблица `voice_cost_alerts`: одно уведомление в сутки. Предельная длина записи — 5 минут (решение владельца).

## Расход и уведомления

Лимитов на число запросов нет. Если расход за сегодня (оценка по ставкам из настроек) в `VOICE_COST_ALERT_FACTOR` раз
(по умолчанию 3) выше среднего за прошлые дни с диктовкой и не меньше `VOICE_COST_ALERT_MIN_USD` (по умолчанию $0,5),
владельцу приходит одно сообщение в Telegram. Ставки `VOICE_*_USD_*` — оценочные, сверить в кабинетах OpenRouter и ClaudeHub; цена распознавания берётся из ответа OpenRouter, ставка — запасная.

## Настройка на сервере

`OPENROUTER_API_KEY` (распознавание; он уже есть для доски) и `WHITEBOARD_PROXY_URL` (с сервера OpenRouter напрямую
отвечает 403, поэтому звонки идут через тот же доверенный прокси, что и у доски), `VOICE_API_KEY` (≥32 случайных символа, для ботов), ключ шлюза моделей уже есть
(`XAI_API_KEY`). Миграция `0010` создаёт две таблицы. Модель правки: `VOICE_CLEANUP_MODEL` (по умолчанию
`claude-haiku-5-5`; проверить, что шлюз отдаёт модель под этим именем).

## Проба на реальных записях

`python -m app.voice.cli запись1.ogg запись2.ogg --project sto` — печатает «как распознано» и «как исправлено». База при
этом в памяти, боевая не затрагивается.

## Выбор модели распознавания

Groq из России закрыт, поэтому распознавание идёт через OpenRouter. Модель меняется одной настройкой
`VOICE_STT_MODEL` (кандидаты для сравнения на реальных записях: `openai/whisper-large-v3`, Microsoft MAI-Transcribe 2,
GPT Transcribe). Сравнение: `python -m app.voice.cli` с разными значениями `VOICE_STT_MODEL`.

## Первая подключённая страница: «Чем помочь?» (диспетчер)

В строке ввода главной страницы рядом с кнопкой отправки есть микрофон: нажал — идёт запись (красная кнопка и таймер),
нажал ещё раз — текст появляется в поле. Сам диктовка ничего не отправляет: человек читает текст и жмёт «Отправить».
Пока идёт запись, над строкой ввода живёт поле «Слушаю…» со словами, распознанными к этому моменту: раз в пару секунд
страница отправляет на `POST /studio/voice/preview` всю запись целиком (следующий запрос — только после ответа на
предыдущий), поэтому текст не «прыгает» кусками. Это сырое распознавание без правки, ничего не хранится, но каждый
запрос считается в расходе (`voice_usage`, исход `preview`). По стопу поле меняется на «Правлю текст…», вся запись идёт
на `/studio/voice/dictate` (распознавание + корректор), готовый текст ложится в строку. Если итоговый запрос не удался,
уже показанные слова вставляются в строку как распознано. Если распознавание не настроено (503), живое поле просто
молчит, а запись и итог работают как раньше.
Если модель что-то поправила, под полем видно «Поправил: вин → VIN» и кнопку «Вернуть как сказано». В запрос уходят
запись, длительность, последние до трёх реплик диалога и имя продукта (для его словаря, если у продукта есть словарь).
Запись автоматически останавливается на `VOICE_MAX_AUDIO_SECONDS` (5 минут). Кнопка скрыта в браузерах без записи звука.
Микрофон работает только по HTTPS. Страница обращается к `/studio/voice/dictate` (вход и проверка источника Студии).
