- Ограничение Telegram проверяется до утверждения и создания отправки, включая UTF-16 и эмодзи. Просроченный процесс отправки получает неоднозначный статус и требует ручной проверки канала, без автоматического повтора.

- Совпадение заданий учитывает весь бриф. Исправлены fallback-тексты и нормализация видеосценария.
- Для обнаруженных неподтверждённых числовых обещаний требуется явная проверка владельцем. Это эвристика, а не универсальная проверка достоверности.
- Бизнес-API требует аутентификацию. Опциональный приватный `STUDIO_USERS_FILE` ограничивает аккаунт заданными компаниями. Административный аккаунт сохраняет общий доступ.
- API получает настройки Telegram из production Compose; `/health/version` показывает точный релиз.

## Доступ

Операторские реквизиты задаются приватно через `STUDIO_ADMIN_USERNAME`, `STUDIO_ADMIN_PASSWORD`, `STUDIO_PUBLIC_ORIGIN=https://…`.
Для отдельного клиентского аккаунта: JSON-файл, где имя пользователя соответствует `{ "password_hash": "pbkdf2_sha256$600000$<salt hex>$<hash hex>", "product_ids": ["<UUID>"] }`.
Соль случайная, хеш PBKDF2-HMAC-SHA256. Файл должен быть доступен контейнеру API по пути `STUDIO_USERS_FILE`; не добавлять его в git. Без файла используется операторский доступ. Интерфейс управления аккаунтами и сессионный вход в этот патч не входят.

## Проверки

Полный pytest и регрессии создания, утверждения, редактирования, изоляции компаний, календаря, восстановления неизвестной отправки, 501 будущей публикации, миграции и числовых обещаний выполняются локально без внешнего LLM и отправки сообщений.
Визуальная проверка в реальном браузере и smoke-тест production должны выполняться после доступа к серверу. Успешные HTML-тесты не заменяют проверку реального интерфейса.
