# ServGo Growth Studio — VK ID и публикация на стене

Рабочая ветка: `feature/vk-oauth-autopublish-20261106`. Реальная авторизация и внешний вызов `wall.post` ещё **не выполнялись**; до живого теста нельзя считать интеграцию подтверждённой.

## Функциональность

- В `/studio/products/{product_id}/channels` есть ссылка «Управлять VK», ведущая на `/studio/products/{product_id}/vk`.
- Авторизация VK ID идёт через `https://id.vk.ru/authorize` и server-side OAuth 2.1 PKCE (S256), десятиминутное одноразовое состояние в HttpOnly SameSite=Lax cookie. Обратный адрес привязан к canonical ServGo; нельзя подменить организацию.
- Перед подключением VK ID проверяется статус редактора/администратора сообщества через существующий адаптер комментариев. **Но это не доказывает доступ к `wall.post`**.
- В ноябре 2026 зафиксирована практическая несовместимость токенов типа `vk2.a.*` из нового VK ID с записью на стену (`wall.post`, ошибка 1051); см. https://github.com/gitroomhq/postiz-app/issues/1408 . Подключение VK ID оставлено как проверяемый путь для приложений с надлежащими разрешениями, но без обещания, что публикация заработает.
- Практическая альтернатива: владелец открывает выпадающую секцию «Ключ сообщества», вставляет официальный API-ключ конкретного сообщества. Токен сохраняется **только в зашифрованном интеграционном хранилище на сервере**, не в базе и не в JS. Получение ключа выполняет владелец через настройки своего VK-сообщества. **Ключ также должен пройти живую проверку публикацией, само сохранение не подтверждает права**.
- Очередь принимает только утверждённые `channel_text` материалы с `channel="vk"`. Имеется защита версии и отпечатка, от запрещённой остановленной кампании, редакторских незавершённых задач и повторного назначения поста.
- Отправляются **только текстовые сообщения**, без изображений/видео. `wall.post` от имени нужного сообщества с постоянным `guid` для ID публикации. Успех записывается по реальному `post_id`; сетевая неопределённость превращается в `delivery_unknown`, без автоматического повтора.
- В режиме выключенного worker можно безопасно проверить интерфейс и создание очереди, но новая запись **не выходит** во ВКонтакте.
- Изоляция бизнесов: Studio SSO, Origin/CSRF, `product_id`, владельческая валидация материала, точный ID сообщества. Публикации и настройки разных компаний не смешиваются.

## Конфигурация

В контейнере API и worker:

```env
SOCIAL_VK_CLIENT_ID=<numeric_web_application_id>
SOCIAL_VK_REDIRECT_BASE=https://servgo.ru
CONTENT_VK_AUTOPOST_ENABLED=false
```

У VK ID приложения необходимо зарегистрировать точный redirect URI:

`https://servgo.ru/studio/social/vk/callback`

При публикационном тесте на отдельном тестовом сообществе поставить `CONTENT_VK_AUTOPOST_ENABLED=true` в переменных окружения **worker** (не в коде), проверив права, архив и состояние очереди. Поставьте вначале один безопасный тестовый текстовый пост.

## Пошаговая проверка

1. Запустить `python -m pytest -q tests/test_vk_publishing.py tests/test_comments.py tests/test_telegram_publishing.py` локально в Codespace с установленными зависимостями. Здесь тесты не запускались; нельзя утверждать, что они зелёные.
2. Проверить в UI `/studio/products/<product_id>/vk`: анонимный GET/POST, tenant SSO, Origin/CSRF и корректность тёмной темы на Android.
3. При наличии VK ID приложения попробовать вход редактора тестового сообщества. Если VK ID выдаст токен, а `wall.post` откажет с 1051, не отмечать канал как работоспособный для автопубликации.
4. Для запасного пути с ключом сообщества владелец сам создаёт ключ в разделе «Работа с API», вводит на странице ServGo и выбирает заранее утверждённый тестовый VK-пост; внешний отправитель работает лишь с явным флагом.
5. Дождаться `published` с нативным ID VK или честного `delivery_unknown`. При неопределённом статусе проверить стену вручную перед записью результата; повторный автоматический вызов недопустим.
6. Проверить отказ с чужим product_id и чужим материалом, смену ключа до отправки, дубль `guid`, отмену и отключение. До подтверждённого результата не включать VK для всех клиентов.

## Область завершённой работы

Только серверный код, Studio UI и регрессионные тесты в отдельной ветке. **Ни одна реальная публикация в VK не подтверждена; production не изменён; CI не запускался вручную.** Варианты с визуальными вложениями, многими VK-сообществами для одного бизнеса и автоматическим назначением слотов редакционного плана отдельно не реализованы.
