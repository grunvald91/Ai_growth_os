# ServGo Growth Studio — переработка страницы «Задания» (21.11.2026)

## Цель
Экран должен за один взгляд отвечать: что требует решения, что сейчас выполняется, какой результат получен. Важен путь «Создать → Задания → Результат», без технического журнала, ложного прогресса и обязательных ручных согласований там, где разрешена автоматизация.

## Проверенные источники
- Жесты Emil Kowalski: https://aiforui.dev/skills/gestures — drag, инерция, предсказуемое закрытие панелей. Основные действия нельзя делать доступными только через жесты.
- Stageshow (Benji Taylor): https://github.com/benjitaylor/skills/tree/main/stageshow — применяем к композиции и демонстрациям, не подменяем этим скиллом требования рабочего UI.
- GoogleChrome Modern Web Guidance: https://github.com/GoogleChrome/modern-web-guidance — content-first-noise-reduction, form-factor-adaptation, card, responsive-design, accessibility, tabs.

## Правила интерфейса
1. Одинаковые понятные названия: «Задания» в меню, заголовке и хлебных крошках. Видимый статус относится к задаче, а не к факту публикации.
2. Первое полезное содержание в верхней части экрана; не создавать три огромных блока статистики и дополнительные липкие панели.
3. Карточка: формат/площадка → название → фактическое состояние/этап → последняя активность → понятный переход. «Подробнее» не должно повторять уже видимый текст.
4. В мобильной версии — одна колонка, фильтры на одной прокручиваемой строке, кликабельные цели >= 44 CSS px на touch, без горизонтального переполнения и перекрытия системными панелями.
5. В широкой версии — список и по запросу контекстные подробности; не держать конкурирующий общий блок помощника на странице заданий.
6. Без придуманных процентов, минут до окончания, фиктивных материалов, оплаченных действий или фальшивых пользовательских решений.
7. Производственные публикации и согласования не изменяются при UI-рефакторинге. SEO-автопубликацию после критика не превращать в ручную.
8. Все данные строго по product_id, доступ к задачам/артефактам проверяется сервером.

## Этапы
### P0 — корректность и состав (начат)
- [x] Инвентаризация текущих пяти фильтров, шести контентных агентов, результатов, уведомлений и UI SDK.
- [ ] Собрать отображаемое «требует внимания» не только из Task.waiting_approval, но и из реальных ожидающих проверки Artifact; отдельно учитывать сбои без навязывания действий.
- [ ] Согласовать статус completed с фактическим состоянием результата: «подготовлено» не равно «опубликовано».
- [ ] Постепенно включать другие пользовательские типы заданий через явный реестр маршрутов, не открывая внутренние/системные задачи.

### P1 — список и навигация (первая реализация)
- [ ] Заголовок «Задания», одно действие «Создать», компактная навигация по состояниям.
- [ ] Текст карточек без дублирования, понятные подписи, фактическое время создания, согласованные визуальные сигналы.
- [ ] Сначала требующие внимания, затем выполняющиеся, далее завершённые; сортировка без потери старых активных задач.
- [ ] Никаких вложенных интерактивных элементов в ссылку карточки; UI SDK и его доступный fallback сохранить.

### P2 — поиск и масштабируемость
- [ ] Серверный поиск по названию, теме брифа и типу работы, фильтр периода, постраничная навигация без усечения результатов.
- [ ] Реальные счётчики статусов (без замены общего количества длиной первой страницы).
- [ ] Обновление статусов без полного reload, сброса фокуса/прокрутки или потери набранного текста.

### P3 — детали задания
- [ ] Для готового задания сначала фактический результат и действия, затем сворачиваемые этапы и история.
- [ ] Для сбоя сначала понятная причина и безопасное продолжение с сохранённых этапов.
- [ ] Отдельная защита от повторных платных запросов и случайной повторной публикации.

### P4 — адаптация и верификация
- [ ] Мобильные ширины 320/360/390/430, планшет 768, desktop 1024/1440, светлая и тёмная темы.
- [ ] Касания, клавиатура, фокус, VoiceOver/TalkBack, экранная клавиатура, prefers-reduced-motion, safe area.
- [ ] Smoke: заполненные/пустые задания, результаты, ошибки, длительные активные задачи, границы компаний, фильтры, прямые ссылки, автоматическое обновление.
- [ ] После зелёного CI — отдельное решение о merge и выкладке с визуальной проверкой actual production.

## Границы
Не строим Kanban с перетаскиванием: сервер управляет состояниями, ручное переставление карточек не имеет бизнес-смысла. Не добавляем свайп как единственный способ действия. Не включаем показ сложных технических полей по умолчанию. Не меняем workflow публикации, разрешения API и платные лимиты.
