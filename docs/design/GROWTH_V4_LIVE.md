# Рабочее переключение дизайна Growth OS

Старые страницы получают кнопку «Новый дизайн». Она устанавливает предпочтение `growth_design=v4` и сохраняет текущий URL и параметры. В новом интерфейсе есть обратная кнопка «Старый дизайн». Предпочтение хранится в HttpOnly SameSite=Lax cookie; при HTTPS — Secure. По умолчанию остаётся прежний дизайн. Переход через выбор компании и редиректы также сохраняет предпочтение.

## Реальные функции

Рабочий документ собирается из CSS, структуры, SVG и компонентов `growth_os_v4_preview.html`. Демонстрационный JavaScript отсекается полностью. Главная использует композицию v4: приветствие, свободное пространство, командная строка с микрофоном и подсказки. Реальные сообщения, подтверждения и голос обслуживает прежний dispatcher.js.

Создание использует карточки формата v4 и рабочие поля. Доска заданий и библиотека загружают записи компании через `/studio/products/{id}/v4/data`; технические артефакты исключены. Карточки показывают последние 200 записей, полный список с серверными фильтрами доступен ниже. При ошибке загрузки исходный список остаётся доступен. SEO показывает этапы v4 и реальные отчёты. Формы остальных разделов размещаются в структуре v4 с сохранением контролов. Исходные формы, имена полей, DOM-цели, скрипты, обработчики, проверки авторизации и CSRF сохраняются. Реальные диспетчер, подтверждения, обновления задач и голос используют прежние API. Формы с ошибками 422 и ответы после сохранения также сохраняют выбранный дизайн.

Все инструменты доступны через боковую навигацию и мобильное «Ещё»: создание, задания, согласование, материалы, планы, календарь, видео, каналы, аналитика, комментарии, разведка, профиль, аккаунты, модели и настройки агентов. Доступ к административным разделам определяется прежними проверками backend.

Добавлены страницы:

- `/studio/products/{id}/seo`: реальные семантические ядра, SEO-планы и отчёты выбранной компании. Запуск через диспетчер; ссылка заполняет команду, отправку делает пользователь. Внешние запросы и расходы не запускаются при открытии страницы.
- `/studio/products/{id}/campaigns`: реальные маркетинговые эксперименты, каналы и бюджеты. Планирование через диспетчер, контент-планы через действующую форму, почтовые кампании — через ServGo Mail.

Почта открывает рабочий модуль `https://servgo.ru/mail` с его собственным входом и полномочиями. Это не новая копия SMTP-модуля. Новая оболочка использует существующие рабочие формы разделов; отдельный демо-макет `/studio/design-preview` остаётся инструментом дизайна, его демонстрационные кнопки не включаются в production UI.

Неизвестные суммы не отображаются как нулевые. В SEO показываются только записи выбранной компании, технические checkpoint/attempt-артефакты не выводятся. SVG ServGo скопирован в исходный v4 из канонического SVG без изменений и используется в рабочем документе, фирменные цвета логотипа отделены от темы интерфейса.

## Проверки

```bash
python -m pytest -q
python -m pip install playwright
python -m playwright install chromium
python scripts/check_growth_live.py
# Или: python scripts/check_growth_live.py --browser /usr/bin/chromium
```

Браузерный тест запускает локальное приложение с отдельной SQLite-базой, создаёт задачу, вызывает детерминированную команду рабочего диспетчера, проверяет 32 страницы/размера и три общих раздела, тему и переключатели. Внешние модели, отправка почты и публикации не вызываются.

Pytest проверяет переключение, сохранение query, cookies и исходных форм, ошибки валидации, создание задачи, CSRF, запрет анонимного доступа и изоляцию компаний. Дополнительно проверяются отсутствие демонстрационного JS в рабочем документе, отсутствие чужих/технических записей в карточках, мобильное «Ещё», реальная карточка созданного задания и отсутствие горизонтального переполнения.

## Выкладка и откат

Использовать существующий `deploy-growth.yml` с точным commit SHA. Новые зависимости и миграции не требуются. Деплой сначала выполняет полный pytest, затем проверяет расхождения с сервером, активные задания, здоровье приложения и выполняет откат при ошибке.

После выкладки проверить вход, переключение в обе стороны, создание задания, доступ к материалам и сохранение компании в контексте. Старая версия доступна по кнопке «Старый дизайн» без серверного отката; полный откат — штатным `deploy_growth.py rollback`.
