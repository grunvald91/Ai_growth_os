# ServGo Growth OS v4 — ветка ревизии интерфейса

**Ветка:** `design/growth-os-v4-review-20261030` (ответвлена от main 30.10.2026)
**Статус:** только интерактивный дизайн-прототип, не новая production-версия.
**Файл:** `app/api/assets/growth_os_v4_preview.html`
**Маршрут:** `GET /studio/design-preview` — требует авторизации Studio; отключён по умолчанию.

## Как открыть локально

С установленными зависимостями AI Growth OS:

```bash
export GROWTH_DESIGN_PREVIEW_ENABLED=1
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000/studio/design-preview` после входа в Studio.
Без запуска приложения можно просто открыть файл `app/api/assets/growth_os_v4_preview.html` в браузере.

## Что не изменено

- Основные маршруты `/studio/products/*`, `/studio/team`, `/studio/voice/*`, `/public/blog/*` остаются на прежних обработчиках.
- Защиты авторизации, CSRF, модельный роутер, генерация и публикация не менялись.
- Демо-команды, метрики, почта, кампании и подтверждения внутри HTML не обращаются к реальным API. Ничего не отправляют и не публикуют.
- Настройка `GROWTH_DESIGN_PREVIEW_ENABLED` по умолчанию отсутствует — маршрут отдаёт 404.
- Для этой ветки **не требуется** запуск GitHub Actions или деплой production. Полноценная интеграция с backend — отдельный этап после принятия UI.

## Карта экранов и интеграции
**Статус:** интерактивный дизайн-прототип, без API и production-изменений. Данные экранов демонстрационные. Источники — анализ репозиториев `grunvald91/Ai_growth_os` (main `8a87d1b` (основание ветки), 28.10.2026) и `grunvald91/booking_bot` (main на дату чтения). Эта карта фиксирует точки входа, а не гарантирует наличие любого перечисленного поведения в production.

## Принцип интерфейса

- **Главная до запроса:** приветствие, крупная командная строка, микрофон, четыре ненавязчивые подсказки. Нет панели метрик и отвлекающего правого блока.
- **Главная после запроса:** ответ диспетчера, карточки с данными и источниками, кнопки следующего действия. Голос и текст используют один маршрут.
- **Десктоп:** левая навигация по модулям, основной рабочий экран, контекстная панель только после перехода в конкретные инструменты или после команды.
- **Мобильная версия:** нижние пункты «Главная / Создать / Задания / Почта / Ещё», остальные разделы доступны в «Ещё». Не нужен горизонтальный скролл страницы.
- **Любое расходное, массовое или публикационное действие** — явный показ последствий и подтверждение; локальные кнопки прототипа ничего не отправляют.

## Переименование видео

**Новое название в интерфейсе:** «Простое видео» (в меню создания и сценарии запуска).

**Подпись:** «Для объяснений, инструкций и простой анимированной рекламы».

**Расширенное описание:** «Поможем сделать понятное короткое видео: текст, озвучка, схемы, изображения, простая анимация и готовый MP4. Не предназначено для сложных реалистичных сцен».

**Техническая совместимость:** API, route и имена задач `whiteboard` не менять ради UX: использовать человекочитаемый display label в UI. Сохранить текущие этапы подтверждения затрат, просмотра, отмены, возобновления и восстановления.

## Что остаётся при подключении реального фронтенда

1. Проверить соответствие каждому текущему endpoint — не удалять старые возможности при смене визуального слоя.
2. Вынести общие дизайн-токены и UI-компоненты из стиля BookingBot: текст, цвет, кнопки, карточки, модалки, состояния, обработку ошибок.
3. Подключить действующие API c проверкой полномочий и CSRF, изоляцией компаний и подтверждением рискованных действий.
4. Доработать маршруты кампаний, чтобы единая форма действительно управляла разными каналами и экспериментами.
5. Связать почтовый интерфейс из BookingBot через единый вход и API; не перемещать отправку SMTP в браузер.
6. Голосовая строка: браузерный захват / STT, диспетчер, подтверждения, результат, доступный текстовый ввод.
7. Добавить договор о состоянии карточек: queued/running/awaiting_review/published/failed/cancelled и исторические события.
8. Ограничения SEO-завода и проверка итогового текста критиком должны быть исправлены до полной автономной публикации.
9. Проверить доступность на сенсорных устройствах, экранные дикторы, управление клавиатурой, `prefers-reduced-motion`.
10. Регрессионно проверить все прежние маршруты и пользовательские пути до выкладки на сервер.
