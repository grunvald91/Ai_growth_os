# ServGo — стандарт уведомлений и предупреждений

Утверждён 25.11.2026. Применять к новым и существующим страницам ServGo, мобильным и десктопным, в обеих темах.

- Многострочные сообщения: скругление 8–12 CSS px (по умолчанию 10), внутренние отступы 12 px, обычный вес текста, межстрочный интервал 1.5–1.6.
- Карточки: скругление 12–16 px. Овальные формы только для коротких меток, компактных индикаторов и подходящих кнопок, не для абзацев.
- Заголовок и важные значения выделяются отдельно; не использовать полужирное начертание для всего многострочного текста.
- Семантические акценты: информация — синий, предупреждение — приглушённый жёлтый, ошибка — красный, успех — зелёный. Использовать токены активной темы; текст остаётся контрастным, смысл не передаётся только цветом.
- Длинные диагностические сведения — раскрываемый блок; причина, необходимые действия и время следующей попытки остаются видимыми. Не скрывать критические для оплаты или безопасности условия.
- Сохранять семантику role="status"/role="alert", hidden, ссылки, клавиатурную доступность. Длинные слова, URL и идентификаторы не должны расширять страницу.

## Реализация в Studio

Общий слой v4: `app/api/assets/growth-servgo-air.css`. Совместимый слой классического Studio: `app/api/content_studio_refresh.py`. Для длинных сообщений использовать p/div/section/aside/article с sg-warning, sg-notice или соответствующим семантическим классом. Inline span.sg-warning остаётся короткой меткой. role=alert сам по себе не означает красную ошибку; для явной ошибки формы использовать sg-form-error, для sg-warning при необходимости sg-message--error.

При ревью проверять: ширины 320/360/390 и desktop 1280 px, светлая/тёмная темы, длинный текст, ссылки, скрытые состояния, короткие метки, журнал ошибок, отсутствие горизонтального скролла. Не менять бизнес-логику, лимиты, модели и расписание повторов ради визуальной правки.

## Отдельные оболочки

- AI Chat: `app/api/ai_chat_assets/ai-chat.css` — уведомление композера, голосовое сообщение и toast.
- BookingBot (встроенный в монорепозиторий): `services/booking_bot/web/frontend/src/styles/design-system.css` — абзацы с role=alert, ds-error, ds-notice и toast; клиентская запись дополнительно использует booking-flow.css.
- Mail: `services/booking_bot/web/api/routes/servgo-mail-air.css` — toast и #notice; не изменять позицию и управление видимостью.
- Новые блочные предупреждения в BookingBot используют ds-notice и модификаторы ds-notice--warning/error/success. Не применять к role=alert на целых экранах или диалогах.

Проверка и выпуск каждой оболочки выполняются отдельно в штатных CI/CD.
