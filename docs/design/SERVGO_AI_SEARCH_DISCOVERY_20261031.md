# ServGo — статьи в обычном поиске и AI-ответах (31.10.2026)

## Цель и пределы обещаний

Речь не о отдельном «ИИ-блоге». Каждая полезная статья компании на
`https://servgo.ru/business/{business_id}/blog/{slug}` должна быть
доступна человеку, обычному поисковому роботу и поисковым системам,
которые используют внешние страницы в ответах. **Попадание в ответы
и цитирование не гарантированы.**

Официальные источники:
- Google Search Central, *AI features and your website*:
  https://developers.google.com/search/docs/appearance/ai-features
  Для AI Overviews/AI Mode нужна индексируемая страница с доступным
  поисковым фрагментом. Отдельная AI-разметка не требуется.
- OpenAI, *Publishers and Developers — FAQ*:
  https://help.openai.com/en/articles/12627856
  Для контента в ChatGPT Search не закрывать `OAI-SearchBot` в
  `robots.txt`; разрешать его запросы через CDN, WAF и сервер.
- Bing, *AI Performance in Bing Webmaster Tools* (2026-02-10):
  https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/
  Отчёт о ссылках-цитированиях, цитируемых страницах и поисковых
  запросах, по которым контент использован для AI-ответов.
- Bing, *Topics Portfolio (Beta)* (2026-10-13):
  https://blogs.bing.com/webmaster/2026/10/introducing-topics-portfolio-beta-in-ai-performance/
  При наличии достаточных данных темы цитирований группируются.
- Яндекс Вебмастер, как работает поиск:
  https://yandex.ru/support/webmaster/ru/yandex-indexing/site-indexing
  Роботу требуются открытые, полезные страницы, ссылки и sitemap.
- Google, *People-first content*:
  https://developers.google.com/search/docs/fundamentals/creating-helpful-content
  Нужны оригинальные факты, ясность, смысл и точность, не искусственный
  объём или плотность ключей.

## Подготовлено в коде

1. В BookingBot серверный HTML содержит полный читательский текст,
   объяснения и реальные факты компании, а не JS-заглушку.
2. У статей: уникальный canonical, title, description, открытый сниппет
   `max-snippet:-1`, действительные `datePublished`/`dateModified`,
   JSON-LD `Article` с URL, именем издателя, бизнес-страницей, языком
   `ru`, тематическим запросом и ссылкой на корпоративный блог.
3. В `robots.txt` для `servgo.ru` группа `User-agent: *` допускает
   `/business/*/blog/*` и `OAI-SearchBot` как часть этой группы;
   личные страницы закрыты. Состояние реальных WAF/nginx/CDN
   **не проверено**.
4. В sitemap/лентах только опубликованные статьи активных компаний;
   пустые или скрытые страницы не показываются как публичные.
5. В редакционном промпте ответ на поисковый вопрос может существовать
   отдельно от статьи: мысль должна быть самодостаточной, понятной,
   проверяемой и без фиктивных источников, но текст остаётся живым.
   `faq` необязателен.
6. В Growth Studio владелец может скрыть статью из публичного блога и
   вернуть её на исходный URL. Скрытие не запускает новое поколение
   платных LLM-заданий и не удаляет статью.
7. Раздел «Поиск и AI-ответы» показывает реальное число опубликованных
   и скрытых статей компании. Показов, кликов, позиций или цитирований
   **ещё нет**; вместо нулей отображается отсутствие интеграции.

## API поисковых кабинетов — код готов, подключение ещё не выполнено

В Growth Studio → SEO-завод → **«Открыть поисковые показатели»** есть
защищённая страница для владельца (также доступен JSON:
`/studio/products/{product_id}/seo/search-metrics.json?days=28`).
До проверки серверных переменных доступа реальные API-запросы не отправляются.

**Google Search Console, официальный Search Analytics API:**
https://developers.google.com/webmaster-tools/v1/searchanalytics/query

Требуемые серверные переменные, задаются только в секретах
Growth backend/worker, **не в браузере и не в репозитории**:

- `SERVGO_GSC_READONLY_TOKEN` — действующий OAuth access token со scope
  `https://www.googleapis.com/auth/webmasters.readonly`;
- `SERVGO_GSC_SITE_URL` — подтверждённый Search Console property:
  `https://servgo.ru/` либо `sc-domain:servgo.ru`.

Запрос читает завершённые данные за выбранный период (по умолчанию 28 дней,
конец — три дня назад), группирует по `page` и фильтрует префикс
`/business/{id}/blog/`. После получения ответ **ещё раз** ограничивается
списком реально опубликованных статей данной компании. Данные о других
компаниях и скрытых страницах не возвращаются. API отдаёт до 1000 верхних
строк, поэтому суммы относятся только к доступным строкам, а не ко всем
переходам с Google. Кнопка «Проверить индекс Google» обращается к
официальному URL Inspection API только для одной опубликованной
статьи и показывает **состояние версии в индексе**; это не live-тест:
https://developers.google.com/webmaster-tools/v1/urlInspection.index/inspect

**Яндекс Вебмастер**, официальный `query-analytics/list`:
https://yandex.ru/dev/webmaster/doc/ru/reference/host-query-analytics

Переменные:
- `SERVGO_YANDEX_WEBMASTER_TOKEN` — OAuth-токен Яндекс Вебмастера;
- `SERVGO_YANDEX_WEBMASTER_USER_ID` — ID владельца токена из `GET /v4/user`;
- `SERVGO_YANDEX_WEBMASTER_HOST_ID` — ID подтверждённого сервго.ру из
  `GET /v4/user/{user-id}/hosts`; не угадывать его.

Запрашивается отчёт **по URL**, а не по суммарному трафику всего домена;
постфильтр такой же — только собственные опубликованные статьи компании.
API сообщает данные за **последние 14 суток**; используется не более 500
первых строк, поэтому итог ограничен доступной выборкой. Не смешивать
эти числа с 28-дневными цифрами Google.

**Bing AI Performance**: https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/
Отчёт о цитированиях доступен в интерфейсе Bing Webmaster Tools,
но проверенного программного API в этой реализации нет. **ChatGPT Search**:
отдельный подтверждённый поток цитирований также не подключён. Пустое
значение означает неизвестность, не ноль.

Встроенный OAuth refresh, долговременное хранение учётных записей и
подключение кабинетов клиентами **не реализованы**: сервис читает переданный
администратором сервера access token. После его истечения отображается
«источник недоступен», без раскрытия ключа или деталей ответа провайдера.
Это служебный этап для владельца платформы, не OAuth-сервис для арендаторов.

## Не реализовано до подключения внешних кабинетов

- Проверка снаружи публичных URL, robots.txt, WAF и SSL.
- Реальная индексация Google/Яндекса, отправка sitemap, мониторинг
  URL Inspection и предупреждений Вебмастера.
- **Подключить действующие OAuth-токены** к уже написанным адаптерам
  Google Search Console / Яндекс Вебмастера и проверить реальные ответы.
  У Bing AI Performance/Topics Portfolio пока нет подтверждённого
  в этой реализации программного источника. Не подменять неизвестные
  данные нулями.
- Группировка показов и кликов по URL каждой опубликованной статьи
  реализована. **Нужна реальная проверка с подключёнными кабинетами**;
  расширенные отчёты по запросам и темам не настроены.
- Атрибуция посещений статьи из AI-ответов: поисковая система может
  не передавать источник; не приписывать ей конверсии без данных.
- Истинные расходы на LLM вызовы по провайдерам, если нет наблюдённого
  `CostRecord` с подтверждённой суммой.

## Что проверить на отдельном этапе выпуска

- `curl -I https://servgo.ru/business/{id}/blog/{slug}` возвращает 200
  и `text/html`, статическая версия показывает весь материал.
- `https://servgo.ru/robots.txt` разрешает публичные блог-пути
  для Googlebot, YandexBot, Bingbot и OAI-SearchBot, сохраняя
  запреты для личных страниц. Проверять и HTTP-правила CDN/WAF.
- Листинг статей и sitemap содержат только реально открытые страницы.
- Index/Follow и `max-snippet` не конфликтуют с HTTP X-Robots-Tag;
  canonical указывает на единственный публичный URL.
- Разметка соответствует видимым данным; нет выдуманных автора,
  отзывов, цен, рейтингов, FAQ и «экспертных цитат».
- Проверить выдачу поисковиков на тестовых статьях *после*
  подтверждения доступности; отсутствие цитирования не считать
  доказательством поломки.

**Практические изменения production, платные запросы и подключение
кабинетов не выполнялись.** Сначала CI, затем согласованный релиз.
