# ServGo AI Chat — первые три специалиста

Чаты — это серверные профили внутри существующего `/studio/chat`; отдельный агентный процесс не создаётся.

- `business_consultant`: диагностика, проверка идей, экономика услуги, решение по найму.
- `marketer`: позиционирование, каналы, воронка, маркетинговые планы и эксперименты.
- `smm_specialist`: контент по площадкам, видео, комментарии и аналитика.

## Безопасность и архитектура
- Идентификатор выбирается из фиксированного списка; через API нельзя передать произвольный system prompt.
- Роль записывается в беседе и не меняется при смене модели или повторном входе. Новый специалист — новый диалог.
- Контекст компании подгружается только через существующую проверку прав на компанию. Новых прав на Growth/BookingBot/Mail не появляется.
- В текущей реализации профиль действует на текстовые ответы. Режим генерации изображений остаётся исходным, без скрытой подмены промпта.
- Исходные большие методики не загружаются целиком: короткие ServGo-инструкции уже содержат выборочный набор приёмов. Интеграции с исполнением действий пока нет.
- При деплое необходима миграция Alembic `0018`; старые беседы остаются без роли (`null`).

## Исправления по ревью
- Несохранённые черновики изолированы по компании и роли; выбранный специалист для ещё не отправленного сообщения восстанавливается после перезагрузки.
- Для изображений интерфейс явно показывает ограничение: инструкция выбранного специалиста применяется только к тексту.
- Недоступная серверная роль переводит запрос в статус `error` до обращения к провайдеру.
- CI проверяет синтаксис JavaScript отдельно от Python-тестов.

## До включения отдельной оплаты моделей

Начальный allowlist приведён в `app/ai_chat/model_access.py`. Модели Claude Haiku, Gemini Flash (включая Flash Image), DeepSeek Chat/Flash и некоторые GPT mini/nano включены; Sonnet/Opus, старшие GPT, Gemini Pro и Grok помечены `paid`, а неизвестные тарифы — `review`. И `paid`, и `review` неактивны.

Каталог возвращает `access_enabled`, `access_status` и `access_label`. Проверка выполняется при отправке, повторе и исполнении старого запроса из очереди. Цены ClaudeHub не подтверждены, и это не биллинг; до запуска оплаты активация платных моделей не предусмотрена.

## Вторая группа: продажи, копирайтинг, платная реклама

- `sales_manager` — диагностика потребности, работа с возражениями, сценарии ответа на заявки и записи без манипуляции.
- `copywriter` — продающие статьи, лендинги, офферы, редактура с отделением готового рекламного текста от служебных замечаний.
- `ads_specialist` — выбор каналов, рекламные гипотезы, тесты креативов, анализ расходов/заявок/выручки; никаких действий в рекламных кабинетах.

Роли добавляются в прежнюю таблицу `ai_chat_conversations.specialist_id` без новой миграции базы. Существующие записи и сохранённые роли сохраняются. Системные инструкции загружаются только из разрешённых файлов на сервере; фронтенд видит лишь метаданные. Дорогие модели остаются выключенными через `app/ai_chat/model_access.py`.

## Ревью второй группы

- Исправлена потеря черновика после ошибки отправки первого сообщения: при создании беседы черновик переносится с временного ключа специалиста на ключ беседы, а после успешной отправки удаляется.
- Черновики, выбранная роль и активная беседа теперь привязаны к непрозрачной области хранения конкретного Studio-логина и компании, а не только к компании. Старые неразделённые ключи намеренно не читаются, чтобы не показывать черновик другого аккаунта при повторном входе в общем браузере.
- Три колонки выбора специалиста появляются только на широком экране (от 1160 px); на промежуточных размерах используются две, на очень узких — одна.
- Роли и ограничения платных моделей не изменены. Новая миграция БД не требуется.
