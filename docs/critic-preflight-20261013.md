# Внутренний критик — контрольный список перед включением

Реализация: `app/llm/critic.py` (общий `LLMService`), ветка `feat/agent-critic-advisory-20261013`.

## Правило качества
- **Нет ограничения на количество важных замечаний.** Критик выявляет все видимые существенные ошибки, связывает каждую с исходной целью и предлагает конкретное исправление.
- `minor`/косметика не запускает правку; существенные замечания должны быть `major` или `critical`.
- Исполнитель принимает или отклоняет **каждое** существенное замечание, с обоснованием.
- Только одна дополнительная авторская правка. Даже при большом числе замечаний не запускать новые споры.
- Не перегенерировать результат, если критик не нашёл существенных проблем.
- Сбой критика, нарушение исходной JSON-схемы, неправильные ID решений или тайм-аут → сохранить первоначальный структурно валидный результат.
- Никакого нового доступа критика к ToolGateway, публикации, аккаунтам и секретам. Существующее согласование человека сохраняется.
- Ограничения токенов, времени и размера контекста остаются техническими; **они не являются квотой на число замечаний**. Если ответ модели обрезан, не считать аудит полным.

## Приёмочные сценарии
- Исходный результат корректен → только проверка критиком, нет переработки.
- Одно замечание и восемь/более независимых существенных замечаний → каждое рассматривается.
- Критик предлагает косметическую правку → без доработки.
- Некоторые рекомендации полезны, некоторые противоречат задаче → исполнитель выборочно принимает/отклоняет.
- Исполнитель отверг все → остаётся исходный материал.
- Некорректный JSON, повреждённая вложенная схема, неверные ID, недоступная модель/тайм-аут → исходная валидная работа сохраняется.
- Проверить на русскоязычных задачах статьи, видео-режиссуры, планирования, маркетинговой стратегии, бизнес-исследований; убедиться, что факты не выдумываются, первоначальная цель не меняется.
- Отдельно проверить задачи с большим контекстом: возможен статус `skipped_size_limit`, который **не означает прохождение проверки**.
- Сравнить затраты и длительность при `AGENT_CRITIC_ENABLED=false` и `true`. До пилота флаг должен оставаться выключенным.

## Выполненное вне Codespaces
- Код создан и сохранён в отдельной ветке GitHub; основной код и сервер не тронуты.
- Контракт схем проверен отдельно без репозитория на объёмах 0, 1, 3, 8, 25 замечаний, включая вложенные `$defs` и смешанные решения исполнителя.
- **Это не является запуском `pytest` на фактическом коде репозитория.** Требуется запуск указанных команд и испытание ClaudeHub.

## Выход на прод
Только после прохода тестов, ручных проверок, оценки расходов и отдельного согласования владельца: мёржить, разворачивать и включать `AGENT_CRITIC_ENABLED=true`. Не запускать Actions ради этой проверки.
