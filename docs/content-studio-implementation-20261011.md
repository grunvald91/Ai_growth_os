## Следующие функциональные этапы

### 2. Адаптивный оркестратор (важно)

- [ ] Типизированное задание: конкретный формат (post/article/short_video/stories/image/campaign), цель, тема, каналы, аудитория и бренд.
- [ ] Маршрутизатор подбирает только нужные роли/схемы; одиночный пост не проходит всю 13-этапную цепочку.
- [ ] Универсальные, фактологически безопасные fallback-адаптации без предположения, что любой клиент — ServGo.
- [ ] Сквозные тесты для разных ниш и числа LLM-вызовов.
- [ ] Логи промежуточных шагов и понятные технические ошибки без выдачи внутренних данных клиенту.

### 3. Качество

- [ ] Проверка источников фактов, пользы, хука, CTA, неудачных повторов и подлинной адаптации.
- [ ] Оценка с объяснениями и ограниченным числом исправлений, без искусственных метрик.
- [ ] Тон и допустимость юмора берутся из профиля конкретной компании.
- [ ] Набор эталонных заданий минимум для пяти разных ниш, автоматические и экспертные критерии приёмки.

### 4. Редактор материалов (после auth)

- [ ] Редактор, сохранение, откат, предложение ИИ, посекционное подтверждение и финальное утверждение.
- [ ] Предпросмотр Markdown/видеокадров и экспорт полного контента.

### 5. Публикации и календарь

### 6. Аналитика

## Важное ограничение

Проектный README предупреждает, что API не содержит собственной авторизации; compose привязывает порт к localhost, но это **не доказывает**, что внешний reverse proxy закрывает все пути. Поэтому расширять права записи и тем более выкладывать эту ветку без отдельной проверки защиты нельзя.
