ВАЖНО: это **временный административный вход**, не многопользовательская авторизация SaaS.
Один пароль даёт доступ ко всем компаниям в Studio. До привлечения клиентов
нужны индивидуальные учётные записи, роли и проверка доступа к `product_id`.
Другие API-роуты FastAPI этой временной защитой не закрыты; reverse proxy
не должен выставлять их публично без отдельной проверки.
Для продуктивного деплоя сначала безопасно создать длинный секрет владельца
в непубликуемой `.env` на сервере, затем отдельно проверить HTTPS и ответ 401/503.
Не выкладывать без выполненного `pytest` и проверки edge-прокси.

## Следующая итерация: календарь, Telegram и креативные брифы (код готов, тесты не запускались)

- [x] `reschedule_slot`: перенос одной публикации с сохранением исходного контента, дедлайна подготовки и статуса; проверка горизонта и пересечений.
- [x] Telegram-управление переносом через отдельную кнопку слота и ввод даты владельцем.
- [x] `telegram_publishing.py`: проверка `getMe` + `getChat` + `getChatMember`; принимаются именно Telegram-каналы, где управляющий бот администратор с правом публиковать.
- [x] Несколько каналов на компанию; дублированное подключение обновляет запись без создания ещё одной. Токены у пользователя не запрашиваются.
- [x] Публикации требуют статуса `APPROVED`, явного назначения даты и выбора канала. Можно назначить один пост в несколько каналов.
- [x] Связь с действующим редакторским планом: Telegram-слот → утверждённая Telegram-адаптация → канал → дата из плана. После подтверждённого API-ответа сохраняются `Publication.status=published` и ID сообщения; план показывает `published`.
- [x] Запланированную публикацию можно отменить до начала отправки. Перенос при назначенной публикации запрещён до её отмены.
- [x] Идемпотентность: CAS-переход `scheduled -> sending` фиксируется транзакцией **до** вызова Bot API; на неопределённой сетевой ошибке статус `delivery_unknown` без автоматических повторов. При краше во время отправки статус `sending` также требует ручного разбора, не автоповтора.
- [x] Ограничение опоздавших отправок: если запланированный момент прошёл более чем на `CONTENT_TELEGRAM_MAX_LATENESS_MINUTES` (по умолчанию 30), задача получает `missed`, сообщение не отправляется. Владелец может снять заведомо неотправленную запись и назначить другую дату.
- [x] Неподтверждённая/неопределённая отправка отображается отдельно в календаре; она не превращается автоматически в «опубликовано» и не стирается обычным обновлением готовности.
- [x] Автоотправка при `CONTENT_TELEGRAM_AUTOPOST_ENABLED=true` только в worker; значение по умолчанию `false`, и Telegram owner UI получает то же состояние переменной.
- [x] `creative.py`: отдельная очередь `content_creative`, 2 агента (стратег и режиссёр) для `short_video`, `story`, `static_image`, проверки схемы, платформ, длительности, непрерывности кадров и подтверждения источников.
- [x] Telegram owner UI: формат → площадка → тема → подготовленный `creative_brief` → согласование. В Growth Studio этот бриф доступен для чтения.
- [x] Новые офлайн-тесты: `test_content_creative.py`, `test_telegram_publishing.py`, `test_telegram_content_owner_publishing.py`; локальный скрипт проверки дополнен ими.

## Важное ограничение

Проектный README предупреждает, что API не содержит собственной авторизации; compose привязывает порт к localhost, но это **не доказывает**, что внешний reverse proxy закрывает все пути. Поэтому расширять права записи и тем более выкладывать эту ветку без отдельной проверки защиты нельзя.
