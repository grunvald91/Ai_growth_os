## Реализовано дополнительно: отдельный пост (требует offline-тестов)

- [x] `app/content/quick_post.py`: два специализированных LLM-вызова, стратег и редактор; строгие контракты, учёт токенов и отказ при ошибках данных.
- [x] `queue_content(format="post", channel=...)` создаёт отдельную долговечную задачу; полные пакеты и календарь используют старый маршрут.
- [x] Worker распознаёт `content_request.mode=post` и не запускает полный конвейер статьи.
- [x] Telegram-меню владельца: компания → «Один пост» → Telegram/VK/Дзен/vc.ru/TenChat → тема.
- [x] В результате появляется `channel_text` со статусом `awaiting_approval`; владелец может утвердить его через Telegram. Нажатие повторно идемпотентно. Публикация НЕ выполняется.
- [x] В быстрый маршрут допускаются только завершённые результаты доступного маркетингового исследования; выводы исследований нельзя объявлять подтверждённым спросом.
- [x] Бренд другой компании не подменяется названием ServGo. Для неподходящего выхода применяется безопасный отказ, а не выдача чужого рекламного текста.
- [x] `app/content/fallbacks.py`: универсальная резервная адаптация шести каналов на основе готовой статьи, без заранее зашитого продукта.
- [x] Тесты на очередь, выбор платформы, два вызова, отказ при выдуманных источниках, согласование и отсутствие публикации.

Ограничения: пока добавлен **только формат post**. Адаптивные short_video/story/image,
полноценная библиотека с версиями и независимое редактирование ещё не готовы.
Записи и согласование поста работают через существующую Telegram-авторизацию
владельца; НЕ добавлять веб-POST без защиты пользовательской сессии.
Проверка точности текста и критериев качества LLM всё ещё требует совершенствования.

## Важное ограничение

Проектный README предупреждает, что API не содержит собственной авторизации; compose привязывает порт к localhost, но это **не доказывает**, что внешний reverse proxy закрывает все пути. Поэтому расширять права записи и тем более выкладывать эту ветку без отдельной проверки защиты нельзя.
