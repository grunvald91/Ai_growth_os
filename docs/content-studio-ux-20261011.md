# ServGo Growth Studio — новый пользовательский сценарий и интерфейс

Дата решения: 11 октября 2026. Реализация в `fix/content-studio-workflow-20261011`.
**Состояние:** код сохранён, но тесты и визуальные испытания в Codespaces/браузере не запускались. Production без изменений.

## Задача пользователя и принципы

Собственнику малого бизнеса нужно за короткий промежуток времени:
1. Понять, что ждёт именно его решения.
2. Быстро заказать один материал, не разбираясь в «13 агентах».
3. Посмотреть контент в привычном виде и исправить его обычным языком.
4. Одобрить конкретную версию.
5. Назначить опубликование в подключённый канал, увидеть реальный статус.
6. Вернуться к плану, библиотеке и результатам при необходимости.

Нельзя делать вид, что видео и фотографии уже сгенерированы, когда подготовлены только их сценарии/промпты.
Нельзя превращать утверждение контента в автоматическую публикацию без отдельного решения.

### Откуда взяты интерфейсные паттерны

- **Planable:** единый материал, контекстная проверка и согласование конкретной версии, календарь, список: https://help.planable.io/hc/en-us/articles/21715323068444-Getting-started-with-Planable
- **Buffer:** один вход создания поста и работа с датой внутри календаря: https://support.buffer.com/articles/how-to-use-buffers-calendar-feature-FSSKbH32DN
- **Later:** этапы Plan → Approve → Publish → Analyze без дублирующих разделов: https://later.com/social-media-management-tools/
- **Baymard Institute:** при работе с телефона уменьшать дезориентацию, число навигационных решений и мелких зон нажатия: https://baymard.com/research-articles/mobile-commerce-design

Мы **заимствуем поведенческие паттерны**, а не фирменные цвета/макеты/тексты конкурентов. Варианты требуют реальных юзабилити-тестов с владельцами бизнеса.

## Информационная архитектура

### Основной уровень

- **Главная:** одно явное действие «Создать», сколько материалов ждут проверки, запланировано в Telegram, сколько отправок требуют ручной проверки. Далее только ближайшие сроки и последние материалы.
- **Создать:** выбор одного из пяти форматов — пост, Shorts-сценарий, Stories-бриф, визуальный бриф, полный пакет. Затем площадка, тема, необязательная аудитория и требования. Работа создаётся в backend, без подмены результата демонстрацией.
- **На проверке:** только реальные `awaiting_approval`, включая статьи и видеосценарии полного пакета, а также быстрые посты и креативные брифы. Фильтр «тексты / сценарии». Утверждение и вход в конкретный материал.
- **Календарь:** дата, площадка, тема, дедлайн, состояние, отдельная форма переноса, без пересоздания статьи.
- **Материалы:** статьи, посты, видеосценарии, Stories/креативы; поиск на сервере и постраничная выдача по 24 записи.

### Второй уровень

- Контент-план (утвердить, поставить на паузу, попросить ИИ составить новый по пожеланиям).
- Каналы и публикации (подключить Telegram через проверку бота, расписание, статус, отмена).
- Результаты (без выдуманных охватов или обещаний).

На мобильном нижняя панель содержит **4 действия**: Главная, Создать, Проверить, Календарь.
Остальные инструменты доступны через компактные ссылки на всех страницах.

## Визуальная система

- Нейтральный светлый фон, белые рабочие поверхности, тёмно-синий текст и ограниченный синий акцент только для действий.
- Отступы, единая высота кнопок не менее 44px, ясная иерархия, заметный активный пункт.
- Не более одного главного CTA в конкретном блоке. Второстепенные команды оставлены ссылками.
- Статусы описывают **состояние работы**, а не предполагаемые маркетинговые результаты.
- Прозрачное различие между `scheduled`, `published`, `delivery_unknown`.
- Форма краткая; выбранный формат определяет доступные каналы.
- В материале: читабельный предпросмотр, карточки кадров у Shorts/Stories/изображений, контекстные действия согласования/доработки и история.
- `prefers-reduced-motion`, клавиатурный фокус, подписи форм, мобильная адаптация от 320px; нужна проверка в браузере.

## Файлы

- `app/api/content_studio_ui.py`: страницы «Создать», «На проверке», «Каналы».
- `app/api/content_studio_refresh.py`: дизайн-токены, CSS и JS поведения селектора формата.
- `app/api/content_studio_design.py`: подключение нового оформления с сохранением старых классов.
- `app/api/content_studio.py`: навигация, новый обзор, страница поста/раскадровки, пагинация материалов и новые защищённые web-маршруты.
- `tests/test_content_studio_v5.py`: приёмочные сценарии без внешней отправки.

## Визуальная корректировка по реальным скриншотам (v6, 11.10.2026)

Пользователь прислал полноэкранные скриншоты Android и отображения ПК. На них обнаружены:

- Мобильная нижняя навигация закрывает часть раздела «Ближайшее по плану».
- Мобильные три KPI-карточки повторяют счётчик проверки, подписи слишком мелкие.
- Горизонтальные быстрые ссылки обрываются у правого края экрана.
- В материалах технические имена вроде `telegram derivative brief` и статусы `draft`/`awaiting_approval`.
- Оформление не совпадает с основной платформой: буква «S» вместо настоящего календаря с ручкой, тёмно-синий/голубой не фирменные.
- На широком экране нижняя часть контента неэффективно использует ширину, текст и элементы слишком мелкие.
- На боковой панели скриншота есть повторный «Календарь» и пункты «Комментарии»/«Бизнес-разведка», **которых нет в текущем исходнике Studio sidebar**. Их источник необходимо дополнительно проверить в фактически опубликованной сборке / общем портале / кэше. Не маскировать это неразобранное расхождение утверждением «уже точно исправлено».

### Реализовано

1. **Источник правды для бренда** — `grunvald91/booking_bot/webapp/static/favicon.svg` и `web/frontend/src/components/Logo.tsx`: неизменённый календарь с ручкой, цвета `#0D1B2A` и `#2F5BEB`, написание Serv/Go, Montserrat с системным fallback. Копия SVG находится в `app/api/content_studio_brand.py`; маршрут `/studio/assets/servgo.svg` возвращает официальный значок.
2. **Все места с заглушкой «S»** в Studio заменены на официальный значок, включая боковую панель, мобильную шапку, карточку проекта и предпросмотры.
3. **Мобильное меню больше не накладывается на содержимое**: стало верхней липкой полосой **в обычном потоке** страницы, непосредственно после компактной шапки с логотипом; основной контент следует ниже. Уменьшено лишнее нижнее поле.
4. **Мобильные показатели**: убрана дублирующая первую KPI-карточка (счётчик «на проверке» остаётся в главном CTA), два оставшихся статуса показываются крупнее.
5. **Быстрые ссылки** 2×2, без скрытой горизонтальной прокрутки; названия материалов до двух строк и размер подписей от 11–13px.
6. **Библиотека / последние материалы**: русские статусы и локализованные общие технические имена. Отдельно исправлена выборка: ручные и самостоятельные материалы видны на главной без `task_id`.
7. **Десктоп 921–1180px**: уменьшена ширина боковой панели, две колонки списка последних материалов и ближайших слотов, гибкие отступы.
8. Кэш-версии CSS/JS повышены до `v=7` после второго визуального обновления.
9. В `tests/test_content_studio_v5.py` добавлена регрессия официального логотипа, структуры мобильной шапки/навигации, единственного календаря в HTML sidebar и локализованных статусов.

Пример запуска в Codespaces после установки Playwright и Chromium:

```bash
FULL_TESTS=1 bash scripts/validate_content_studio.sh
python -m pip install playwright
python -m playwright install chromium
STUDIO_URL="https://growth.servgo.ru/studio/products/<company_uuid>" \
  python scripts/check_content_studio_layout.py
```

Если на сервере включён HTTP Basic, перед запуском в окружении терминала
следует установить `STUDIO_ADMIN_USERNAME` и `STUDIO_ADMIN_PASSWORD`; **не
записывать секреты в репозиторий**. Скриншоты по умолчанию остаются в
`/tmp/servgo-studio-ui-qa`. Если production отдаёт старую сборку, проверка
выдаст `Wrong deployed build`, а не ложное заключение о качестве свежего CSS.
