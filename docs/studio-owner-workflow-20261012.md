# ServGo Growth Studio — понятный маршрут владельца (12.10.2026)

Рабочая ветка: `fix/content-studio-workflow-20261011`. Этот документ описывает
**реализованные изменения кода**, а не подтверждение работающего production.

## Что изменено в поведении

### Главная: один вход, никакой головоломки

Первый экран: «Что будем создавать?» → «Создать материал» → «Мои задания».
Сразу ниже — «Сейчас создаётся» или «Последние задания». Остальная детализация
(календарь, сводка контент-плана, метрики и старые пакеты) скрыта в блоке
«Контент-план, календарь и другие инструменты». Ничего из данных не удалено.

Основная навигация для мобильного и ПК теперь состоит из четырёх пунктов:
**Главная / Создать / В работе / Мои материалы**. Контент-план, календарь,
согласование, публикации и аналитика доступны через раскрываемую группу
«Настройки маркетинга и другое» и существующие прямые ссылки.

### После запуска — конкретная страница задачи

Веб-форма `/studio/products/<uuid>/create` создаёт реальный `Task`, после чего
делает HTTP 303 на `/studio/products/<uuid>/tasks/<uuid>`. На странице:
- реальное состояние `queued / running / waiting_approval / completed / failed / cancelled`;
- известные этапы через сохранённые `AgentRun`, без выдуманного процента готовности;
- прямые ссылки на каждый `Artifact` при появлении;
- явная ошибка или кнопка повтора там, где повтор безопасен;
- время от времени — актуализация по реальному API.

Задания всех подходящих маркетинговых агентов находятся в `/work`. Отдельные
фильтры — «Все», «В работе», «Готово», «Ошибки». Старые технические имена
скрываются за человеческими названиями.

### Уведомления

На каждой странице владельца находится раскрываемая кнопка
«🔔 Уведомления». Данные приходят из **реального** `/activity.json`,
ограниченного текущим `product_id`; опрос в видимой вкладке каждые 20 секунд.

События: материал требует проверки, недавний текстовый/визуальный черновик
создан, редакторский план ждёт утверждения, задание завершилось с ошибкой,
а отдельный `video_render` доступен как результат. Нажатие ведёт
на нужный материал, план или ошибочное задание.

Это **внутреннее уведомление во вкладке**, не push на телефон и не Telegram.
«Прочитано» пока не сохраняется, счётчик показывает текущие запросы,
требующие решения.

### Статьи и медиа без фальшивого предпросмотра

Статьи отображаются как безопасный HTML вместо сырого Markdown. Поддержаны
заголовки, выделение, списки, ссылки по HTTP(S), цитаты и блоки кода.
Небезопасная HTML-разметка экранируется. Исходный Markdown остаётся доступен
для копирования и ручного редактирования.

Если `Artifact.kind = video_render` и действительно существует сохранённый
`video.mp4`, страница показывает проигрыватель и ссылки скачивания MP4,
субтитров и сценария. Выдача файлов разрешена только для
авторизованного `product_id` и подтверждённого `video_render`.
Одобрение MP4 отклоняется, если физический файл отсутствует.

`creative_brief` (Stories / Shorts / изображение) остаётся **сценарием и
раскадровкой**. Нельзя скачивать «MP4», которого система ещё не создала.

`editorial_plan` из задачи планировщика тоже регистрируется как результат
и открывается напрямую во вкладке утверждения плана.

## Технические файлы

- `app/api/content_studio_activity.py` — локализованные статусы, история задач,
  их результат, уведомления, этапы.
- `app/api/content_studio_work_ui.py` — адаптивный интерфейс и обновления API.
- `app/api/content_studio_article.py` — безопасный рендер Markdown.
- `app/api/content_studio.py` — навигация, новые страницы, защищённое API,
  просмотр/скачивание готового видео.
- `tests/test_content_studio_activity.py` — новый набор регрессионных тестов.
- `scripts/check_content_studio_layout.py` — браузерная инспекция 7 размеров.
- `scripts/validate_content_studio.sh` — офлайн-проверка + pytest без GitHub Actions.

## Важные ограничения

- [ ] Тесты и реальный браузер **ещё не запущены**: подключение GitHub умеет
      читать/изменять файлы, но не выполнять терминальные команды в Codespaces.
- [ ] Сервер `growth.servgo.ru` **не обновлялся** и может показывать старые
      «Обзор / Комментарии / Ещё» из другого frontend bundle.
- [ ] Рабочая очередь показывает реальные задачи из БД AI Growth OS.
      Для задач анимационной студии Animator, если они живут в другом
      воркере/БД/API, **требуется отдельная интеграция**, которую нельзя считать
      готовой без проверки кодового источника.
- [ ] Нет пользовательских «прочитано» и внешних push-уведомлений. Автопостинг
      Telegram остаётся выключенным по умолчанию.
- [ ] Внешние маркетинговые панели «Бизнес-разведка» и «Комментарии» ещё
      требуют UX-инвентаризации отдельно от текущего модуля `/studio`.

## Приёмка до выкладки

```bash
FULL_TESTS=1 bash scripts/validate_content_studio.sh
# после установки Playwright:
STUDIO_URL="https://growth.servgo.ru/studio/products/<company_uuid>" \
  python scripts/check_content_studio_layout.py
```

Проверять: создание → задачи → этапы → материал → утверждение → публикация;
неудачную задачу и повтор; нормальное отображение статей; видеофайл versus
бриф; доступ только к материалам компании; отсутствие дублей уведомлений;
горизонтальный overflow на телефоне и подмену навигации старой сборкой.
Затем резервное копирование, smoke-тесты, план отката и отдельный деплой.
