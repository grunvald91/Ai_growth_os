# ServGo Growth Studio — единая версия с Animator (13.10.2026)

**Единственная кандидатная ветка:** `wip/studio-unified-workspace-20261013`.
Она **основана на** `wip/whiteboard-video-foundation` (видеогенератор
с отдельным подтверждением платных вызовов, worker, MP4/player, субтитрами,
проверкой прокси, комментариями и бизнес-разведкой), а поверх добавлен
владельческий интерфейс из старой ветки `fix/content-studio-workflow-20261011`.

## Устранены три разрыва кода

### 1. Старое меню: источник найден

Другое меню «Обзор / Комментарии / Ещё» находится в
`fix/content-studio-visual-release-20261012` в функции `mobile_nav_html`
(`app/api/content_studio.py`), а не в рабочей ветке интерфейса.
Это разные исходники, не проблема браузерного CSS.

Единая версия имеет четыре основных пункта: Главная / Создать / В работе /
Материалы. Остальные функции доступны через «Ещё инструменты», включая
комментарии, бизнес-разведку, календарь, публикации и рисованное видео.

### 2. Animator подключён к той же БД и рабочему центру

Это не внешняя система: в исходном whiteboard worker задача хранится в
`Task.assigned_agent=whiteboard_renderer`, состояние — в
`Artifact.kind=whiteboard_job_state`, готовый MP4 — в
`Artifact.kind=whiteboard_video`. Отдельная страница
`/studio/products/{product_id}/whiteboard/{task_id}` уже показывает
сценарий/картинки/озвучку и готовые MP4/SRT/PNG/JSON.

В общем интерфейсе:
- На странице «Создать» есть видимая карточка рисованного видео.
- «В работе» показывает задание Animator и его этап/реальное число API-вызовов.
- Статус `waiting_approval` не считается выполненным и переводится
  «Нужно подтверждение»; пользователь переходит к согласованию перед списаниями.
- Окончание MP4, ошибка и ожидание подтверждения появляются в уведомлениях.
- Готовое рисованное видео видно в «Мои материалы», откроется в
  специализированном плеере с реальной кнопкой скачивания.
- Доступ к чужим компаниям ограничен существующей Studio-авторизацией.
- Сохранены ограничения биллинга: **13–25 вызовов ≠ денежный лимит**,
  неизвестная стоимость показана честно, автоматического повтора нет.

Новый тест: `tests/test_content_studio_animator_integration.py`.
Не использовать прежнюю `fix/content-studio-workflow-20261011` для деплоя:
в ней нет реального Animator worker и других важных модулей.

### 3. Запуск тестов, браузерная проверка и прод

**Ещё не выполнялись в этом сеансе.** Доступный здесь GitHub Connector умеет
редактировать репозитории, но не управлять Codespaces терминалом или SSH
сервера. Локальный Python-контейнер не имеет интернет/DNS доступа
до GitHub и growth.servgo.ru. Не использовать Actions (минуты ограничены).

В существующем Codespaces:

```bash
cd /workspaces/servgo-animator
git fetch origin wip/studio-unified-workspace-20261013
git switch --track origin/wip/studio-unified-workspace-20261013
python -m pip install -e '.[test]'
FULL_TESTS=1 bash scripts/validate_content_studio.sh
```

Не переключать старую рабочую директорию со свободными изменениями:
при `git status --short` с незакоммиченными файлами открыть отдельный
Codespaces или создать временную рабочую ветку/worktree.

Для браузера после запуска локального API и PostgreSQL:

```bash
python -m pip install playwright
python -m playwright install chromium
STUDIO_URL="http://localhost:8000/studio/products/<product_uuid>" \
  python scripts/check_content_studio_layout.py
```

Браузерная проверка охватывает 7 размеров × 6 страниц, маркер
`20261012-work9`, старую мобильную навигацию, переполнение, слишком
маленький текст, поля формы и перекрытие уведомлений.
Расширить список страниц проверкой Animator и завершённого MP4 вручную.

### После зелёной проверки, ДО сервера

1. Проверить фактически запущенный `current` release и наложения whiteboard
   (это **overlay**, не только старый SHA).
2. Проверить отсутствие незавершённых whiteboard job: нельзя
   останавливать worker посередине платной генерации.
3. Не запускать `scripts/deploy_content_studio.sh` автоматически — он
   требует заранее подготовленной отдельной директории релиза,
   полного тестового preflight, бэкапа БД/файлов и ожидаемого commit SHA.
4. После резервной копии и проверенного плана отката — целевой деплой
   API/worker/Telegram по SSH без GitHub Actions.
5. На `growth.servgo.ru` проверить источник HTML/build marker,
   конкретные процессы создания и подтверждения, и скачивание
   настоящего MP4. Секреты и пароли в чат не выводить.

**Состояние по умолчанию: продакшен без изменений.** Все правки этой
кандидатной ветки сохраняются в GitHub, но не объявляются прошедшими
проверку без результатов терминала.
