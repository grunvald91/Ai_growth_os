# Рекламный ролик из кода (прототип)

Вертикальный ролик 1080×1920 с озвучкой: страница `template.html` рисует каждый кадр строго по времени,
голос, субтитры и анимации идут по одной шкале, ffmpeg собирает видео со звуком.

## Запуск (Codespace с 2 ядрами и 8 ГБ памяти)

```sh
tools/ad_video/setup.sh                       # один раз
python3 tools/ad_video/build.py tools/ad_video/script.example.json /tmp/ad_out
```

Готовый ролик: `/tmp/ad_out/ad.mp4` (плюс `timeline.json`, `mix.wav` и кадры для проверки).

## Что внутри

- `script.example.json` — выдуманные данные барбершопа. В продукте название, цвета и тексты берутся из профиля компании.
- Голос Piper (`ru_RU-irina-medium`) только для прототипа; в продукте используется общая озвучка платформы.
- Слова на экране привязываются к голосу по меткам слов (faster-whisper). Если модель недоступна, метки считаются
  пропорционально длине слов.
- Рендер не нужен на основном сервере: у него 1 ядро и 1,8 ГБ памяти.

## Критик (один раз, как в рисованном видео)

```sh
export OPENROUTER_API_KEY=...        # из секретов, не из подсказок
export AD_CRITIC_MODEL=...           # модель с поддержкой картинок
python3 tools/ad_video/review.py tools/ad_video/script.example.json /tmp/ad_out
```

1. Собирается первая версия. Критик один раз смотрит все ключевые кадры, сценарий и замеры (скорость речи, вылезания за безопасную зону).
2. Автор отдельным вызовом решает по каждому замечанию: принять или отклонить. Принять можно только серьёзное (blocking/major),
   уверенное и не про стиль.
3. Если что-то принято, автор правит только тексты и разбивку строк (не бренд, не факты, не структуру), и ролик собирается
   заново один раз. Новая версия берётся, только если в ней нет вылезаний за безопасную зону, иначе остаётся первая.
4. Любая ошибка критика или автора оставляет рабочий первый ролик. Итог: `final.mp4` и `review.json` с решениями.

Стоимость: один вызов критика с картинками, один вызов решения и, если что-то принято, один вызов правки.
